# List type (`ModeList`)

**Status:** approved  
**Branch:** `feat/mode-list`

## Problem

SuperCache has KV, Bloom, Set, ZSet, and Geo. There is no **ordered sequence** (recent events, work queues, activity feeds). Callers store one KV blob and rewrite the whole list on every push, or keep Redis LIST outside SuperCache.

Set/ZSet are the wrong tool: they have no left/right ends and no stable insertion order.

## Non-goals

- Blocking pops (`BLPOP` / `BRPOP`)
- `LSET` / `LINSERT` / `LREM` / `RPOPLPUSH` / `LMOVE`
- Streams / consumer groups
- Per-element TTL
- Changing RF / tombstones / existing Get/Put/Delete / Set / ZSet / Geo / Bloom contracts
- Persistence
- Unbounded lists: `MaxBytes` still bounds the encoded entry
- Changing the **hint identity** scheme (`hintID` is still `ks+name` except BloomAdd)

## Why not item-level fan-out (locked)

Set/ZSet/Geo item-ops are **commutative enough** under owner serialize: missing an earlier Add of a *different* item still leaves a valid set; a later Contains may owner-forward.

List ops are **not commutative**. `LPush A` then `LPush B` ≠ `LPush B` alone.

Today `internal/peer/hints.go` `hintID` for non-`FlagBloomAdd` is `ks + "\x00" + key`. A second mutate of the same name **replaces** the pending hint. If we fan out only `FlagListLPush(B)` while `FlagListLPush(A)` is queued, A is dropped and the replica list is wrong.

**v1 wire:** every mutate fans out a **full encoded list** (`FlagList`) at the post-op version. Hint coalesce keeps the newest snapshot — that is correct. Same install rule as ModeSet handoff (`version ≥ local` and not blocked by tombstone).

Item-level list ops would need a hintID change (version or payload). That is a **separate** design; not this PR.

Rejected for v1: op-log + snapshot-on-gap (more engine paths; first cut is snapshot-only).

## Contract

### API (new; existing verbs unchanged)

On Engine, client, proto, and **`cmd/sc`** (same PR):

| Call | Meaning |
|------|---------|
| `LPush(ks, name, item)` | Prepend. Creates list if missing. |
| `RPush(ks, name, item)` | Append. Creates list if missing. |
| `LPop(ks, name) (item []byte, ok bool, err error)` | Remove and return head. Missing / empty → `ok=false`, nil error. |
| `RPop(ks, name) (item []byte, ok bool, err error)` | Remove and return tail. Missing / empty → `ok=false`. |
| `LLen(ks, name) (int, error)` | Length. Missing → `0`. |
| `LIndex(ks, name, idx int) (item []byte, ok bool, err error)` | Element at index (Redis negatives: `-1` = last). Missing / OOB → `ok=false`. |
| `LRange(ks, name, start, stop int) ([][]byte, error)` | Inclusive window, Redis-style negatives. Missing → empty. |
| `Delete(ks, name)` | Tombstone whole list. |

- `name` is list identity; owner = `Owner(name)`.
- `item` is `[]byte`, max length = `MaxKeyLen`.
- Get/Put on `ModeList` → `ErrInvalidArgument`.
- List verbs on non-`ModeList` → `ErrInvalidArgument`.
- Cross-mode misuse → `ErrInvalidArgument`.

**Not in v1:** `LTrim`, `LSet`, blocking pop, max-length auto-trim knob.

**Empty after last pop:** keep empty entry (`LLen` 0) until `Delete(name)` (same as Set/ZSet/Geo).

### Keyspace

New mode `keyspace.ModeList`.

| Field | Role |
|-------|------|
| `MaxBytes` | Bounds encoded list + envelope |
| `TTL` | Whole list |
| `NegativeTTL` | Ignored |
| `TombstoneTTL` | On `Delete(name)` |
| `ReplicationFactor` | Same as other modes |

### Replication

| Op | Owner | Replicas |
|----|--------|----------|
| LPush / RPush / LPop / RPop | mutate under mutex; bump version | `FlagList` snapshot |
| `Delete(name)` | tombstone | `ApplyDelete` |
| Handoff | full snapshot | `FlagList` if version ≥ local |

One new flag: **`FlagList`** (`1<<13`). No `FlagListPush` in v1.

Hints: `(ks, name)` snapshot; tombstone on `name` supersedes. Newest version wins (existing `hintID`).

Non-replicas: `LLen` / `LIndex` / `LRange` / pop-read-after-forward **forward to owner**. Pops from a non-owner still **Forward/ApplyPut to owner** (owner mutates). Replicas in RF keep a local copy for `LLen`/`LRange`/`LIndex`.

**Pops:** only the owner removes. Client on non-owner sends the pop to the owner; response is the popped item (need a return path). Options (locked):

- Non-owner calls owner via existing **ApplyPut is fire-and-forget / no payload back** — cannot return the popped bytes.
- So pops (and pushes that need only ACK) from non-owner use a **Cache-level forward to owner Engine method** like SetAdd already does (`ApplyPut` of the *new* snapshot is wrong for pop because the caller must get the item).

Locked non-owner path:

- **LPush/RPush:** same as GeoAdd — `ApplyPut` to owner with a **directive** is insufficient if we only have FlagList snapshot (owner must apply the *op*, not install a client-built snapshot).

Therefore owner must apply the **op**, not a client-supplied list:

**Push from non-owner:** `ApplyPut` with new flags is the SetAdd pattern (`FlagSetAdd` payload = item). For list we said no item flags…

**Conflict:** snapshot-only fan-out is for *replicas after owner applied*. Client → non-owner → owner still needs “please LPush this item”.

Locked:

| Hop | Payload |
|-----|---------|
| Client → any node → **owner** | op: `FlagListLPush` / `FlagListRPush` / `FlagListLPop` / `FlagListRPop` + item (pops: empty value) |
| Owner → **replicas** | `FlagList` full snapshot after the op |

So we **do** have item flags, but they are **owner-apply only** (like SetAdd). Replicas **ignore item flags if they somehow receive them**? Cleaner: owner ApplyPut of FlagListLPush applies the op and **re-replicates FlagList** (same as SetAdd on owner re-fans-out). Replicas that receive `FlagListLPush` would have the commutative problem.

**Locked replica apply:**

- `FlagList` → snapshot install (version gate)
- `FlagListLPush` / `RPush` / `LPop` / `RPop` → **apply the op** (same as owner) **only if** we accept the hint-loss risk **or** we treat item flags as owner-directed and replicas still apply them in version order

If replica gets LPush A (v1) then snapshot (v3) that already includes A,B — snapshot wins. If replica misses v1 and gets v2 LPush B only — **corrupt**.

Replica item-apply is only safe if **no op is skipped**. Hints skip ops.

**Therefore replicas must only install `FlagList` snapshots.** Item flags are **owner-inbox only**:

- Non-owner: `ApplyPut(FlagListLPush, item)` to owner.
- Owner `ApplyPut` of `FlagListLPush`: apply LPush, then `replicate(FlagList snapshot)` to R−1.
- Replica `ApplyPut` of `FlagListLPush`: **do not apply as LPush**; if we never send item flags to replicas, this branch is unused.

Owner local `LPush` (client hit owner): apply + replicate snapshot.

Pops from non-owner: ApplyPut cannot return the popped item. Need a response.

**Locked pop RPC path:** non-owner uses peer **GetOrLoad-style is wrong**. Use **ForwardPut-like** dedicated behavior:

Simplest v1 that already exists: non-owner **dials owner Cache/Engine via Transport.ApplyPut** is insufficient.

Look at SetAdd non-owner: it ApplyPuts FlagSetAdd and returns error only — no extra result. Pops need a result.

Options:

1. Add `ForwardListPop` peer RPC — extra proto (peer). Avoid if possible.
2. Non-owner **does not serve LPop**; returns `ErrUnavailable` “pop on owner only” — bad UX.
3. Reuse a small **ApplyPut response** — peer ApplyPut already returns applied bool, not bytes.
4. Non-owner **GetOrLoad after instructing pop** — race.
5. Add peer `ApplyListOp` returning `{item, ok}` — cleanest for pop.

**Locked for v1 (minimize new peer RPCs):**  

- **Pushes** from non-owner: `ApplyPut(FlagListLPush/RPush, item)` to owner; owner applies + snapshot-fans-out. Client ACK = owner applied.  
- **Pops** from non-owner: owner-forward via **new optional field** or reuse Transport if we add `ApplyPut` value-out — too invasive.

Check peer ApplyPut response...

I'll lock: **pop is owner-routed like Delete**. Add **`ForwardListPop`** on the Peer service **or** piggyback Cache client: non-owner Engine calls `Transport` new method `ListPop(addr, ks, name, left bool) (item, ok)`.

That's one small peer RPC. Design it explicitly:

```text
rpc ListPop(ListPopRequest) returns (ListPopResponse);
// left=true → LPop; Request: keyspace, name, left; Response: found, item
```

Owner runs LPop/RPop local + snapshot fan-out; returns item.

Alternatively avoid new peer RPC: **LPop/RPop only legal when local node is owner**; non-owner returns `ErrUnavailable` with message to retry via client seeds (client already multi-seed). That's a product downgrade.

**Prefer:** one peer RPC `ListPop` for non-owner. Pushes stay ApplyPut flags.

If review wants zero new peer RPCs: pop-on-owner-only.

### What existing clients can assume

Unchanged if they never open `ModeList`. No new default demo keyspace in this PR.

## Approach

### In-memory (`pkg/listx` or `pkg/lst`)

Package name: **`pkg/listx`** (avoid clash with Go `container/list` and `cmd` list). Or `pkg/seq`. Default **`pkg/listx`**.

```go
type List struct {
    items [][]byte // index 0 = head (LPUSH/LPOP end)
}
```

`LPush`/`RPush` copy item; `LPop`/`RPop`; `Len`; `Index` (negatives); `Range` (Redis window).

**Encode:** left-to-right records `uvarint(len)+bytes`. Empty → `[]byte{}`.

`ApproxWireBytes` for lazy cost.

### Store

`FlagList`, `FlagListLPush`, `FlagListRPush` (owner-inbox; replicas should not see them in steady state).

Live `lCache *listx.List` + `lDirty` lazy encode. Protect live FlagList from LRU. `LInstall` snapshot version gate.

`LPush`/`RPush`/`LPop`/`RPop` mutate cache; encode on Peek/handoff.

### Engine

`pkg/engine/list.go`. Mode checks. Owner local + replicate **FlagList** snapshot. Non-owner push: ApplyPut FlagListLPush/RPush. Non-owner pop: `ListPop` peer RPC (or owner-only if review drops the RPC). Get/Put reject ModeList. GetOrLoadLocal returns FlagList.

### Client / proto / sc

```protobuf
rpc LPush(LPushRequest) returns (LPushResponse);
rpc RPush(RPushRequest) returns (RPushResponse);
rpc LPop(LPopRequest) returns (LPopResponse);   // present + item
rpc RPop(RPopRequest) returns (RPopResponse);
rpc LLen(LLenRequest) returns (LLenResponse);
rpc LIndex(LIndexRequest) returns (LIndexResponse); // present + item
rpc LRange(LRangeRequest) returns (LRangeResponse); // start/stop int32
```

**`cmd/sc` (required):**

| CLI | Maps to |
|-----|---------|
| `lpush <name> <item>` | `LPush` |
| `rpush <name> <item>` | `RPush` |
| `lpop <name>` | `LPop` (`item` or `(nil)`) |
| `rpop <name>` | `RPop` |
| `llen <name>` | `LLen` |
| `lindex <name> <idx>` | `LIndex` |
| `lrange <name> <start> <stop>` | `LRange` (one item per line) |

### Benchmarks

| Benchmark | Notes |
|-----------|--------|
| `StoreLPush` / `EngineLPush` | rotating items, fixed name |
| `EngineLLen` | **0 alloc** when warm |
| `EngineLIndexHit` | **0 alloc** when warm (no copy? must copy item — 1 alloc OK; document) |
| `EngineLRange` | small window of 1k list |

`LIndex`/`LRange` must copy bytes out of the live slice (same as ZRange). LLen 0 alloc.

KV Get-hit allocs must not rise.
