# Geospatial type (`ModeGeo`)

**Status:** approved  
**Branch:** `feat/mode-geo`

## Problem

SuperCache has opaque KV, Bloom, exact sets, and scored sorted sets. There is no **named point index** (stores, drivers, check-ins) with “points near here.”

Callers today either:

- one KV per member (`geo:city:shop` → `lon,lat` bytes) and scan in the app, or
- keep Redis GEO / a spatial DB outside SuperCache.

ZSet is the wrong tool: scores are not coordinates, and `ZRangeByScore` is not a radius query.

## Non-goals

- Polygons, lines, routes, tiles, or geofence boolean ops
- `GEOSEARCH` BYBOX / FROMMEMBER / STORE (Redis extras)
- Multi-key geo unions
- Per-member TTL (whole-name `TTL` only, same as Set/ZSet)
- Changing RF / tombstones / Get/Put/Delete / Set / ZSet / Bloom contracts
- Persistence across process restart
- Unbounded indexes: `MaxBytes` still bounds the encoded entry
- Exact Redis GEO wire protocol or 52-bit geohash scores as the public API
- Overloading `ModeZSet` with lon/lat-as-score

## Contract

### API (new; existing verbs unchanged)

On `pkg/engine.Engine`, `pkg/client.Client`, Cache proto, and **`cmd/sc`** (same PR as the type):

| Call | Meaning |
|------|---------|
| `GeoAdd(ks, name, member, lon, lat float64)` | Insert or **update position** of `member` in named index. Creates index if missing. |
| `GeoRem(ks, name, member)` | Remove member if present. No-op if missing / index missing. |
| `GeoPos(ks, name, member) (lon, lat float64, ok bool, err error)` | Position if present. Missing member or index → `ok=false`, nil error. |
| `GeoCard(ks, name) (int, error)` | Member count. Missing → `0`, nil error. |
| `GeoDist(ks, name, a, b []byte) (meters float64, ok bool, err error)` | Great-circle distance. Missing either member or index → `ok=false`, nil error. |
| `GeoRadius(ks, name, lon, lat, radiusM float64, limit int) ([]GeoMember, error)` | Members with distance ≤ `radiusM` (meters), **nearest first**, then member bytes. `limit <= 0` → no cap. Missing → empty. |
| `Delete(ks, name)` | Existing Delete: whole index tombstone. |

```go
type GeoMember struct {
	Member []byte
	Lon    float64
	Lat    float64
	Dist   float64 // meters from query point; 0 on GeoPos-only paths
}
```

- `name` is the index identity; ring owner = `Owner(name)`.
- `member` is `[]byte`, same max length as a key (`MaxKeyLen`).
- **Coordinates:** WGS84. `lon ∈ [-180, 180]`, `lat ∈ [-90, 90]`. NaN / ±Inf / out of range → `ErrInvalidArgument`.
- **Distance:** haversine, mean Earth radius **6371.0088 km**. Result in **meters**.
- Get/Put on `ModeGeo` → `ErrInvalidArgument`.
- Geo* on non-`ModeGeo` → `ErrInvalidArgument`.
- Cross-mode misuse (GeoAdd on ModeZSet, ZAdd on ModeGeo, …) → `ErrInvalidArgument`.

**Not in v1:** `GeoHash`, `GeoSearch` BYBOX, `FROMMEMBER`, unit flags (km/mi/ft), `COUNT ANY`, store-to-another-key.

### Keyspace

New mode `keyspace.ModeGeo`.

| Field | Role |
|-------|------|
| `MaxBytes` | Bounds encoded geo blob + envelope |
| `TTL` | Expires the **whole** index |
| `NegativeTTL` | Ignored |
| `TombstoneTTL` | On `Delete(name)` |
| `ReplicationFactor` | Same as KV / ModeSet / ModeZSet |

No extra sizing knobs in v1.

### Replication

Same pattern as **ModeZSet** (owner-serialized writes + item-level fan-out + versioned snapshot handoff):

| Op | Owner | Replicas |
|----|--------|----------|
| `GeoAdd` | upsert lon/lat under store mutex; bump version | `FlagGeoAdd` apply |
| `GeoRem` | remove member; bump version | `FlagGeoRem` apply |
| `Delete(name)` | tombstone | `ApplyDelete` |
| Handoff | full snapshot | `FlagGeo` if incoming version ≥ local |

**Wire:** reuse **ApplyPut** with new flags (no new peer RPC names):

| Flag | Value payload |
|------|----------------|
| `FlagGeo` | full encoded index (handoff) |
| `FlagGeoAdd` | encoded single `{lon, lat, member}` |
| `FlagGeoRem` | member bytes only |

Hints: `(ks, name, "geoadd", member)` / `(ks, name, "georem", member)`; tombstone on `name` supersedes pending member ops.

Non-replicas: `GeoPos` / `GeoCard` / `GeoDist` / `GeoRadius` **forward to owner**. Replicas in RF keep a local copy for local reads.

Owner serializes; **last write wins** for a member’s position.

### What existing clients can assume

- CacheOnly / LoadThrough / Bloom / Set / ZSet unchanged if they never open `ModeGeo`.
- No new default node keyspace unless demos opt in (**examples = separate PR**).

## Approach

### In-memory (`pkg/geo`)

```go
type Point struct {
	Lon, Lat float64
}

type Index struct {
	// member string → lon/lat
	pts map[string]Point
}
```

Ops: `Add(member, lon, lat) error`, `Rem`, `Pos`, `Card`, `Dist(a,b)`, `Radius(lon, lat, radiusM, limit)`.

**v1 query:** scan all members, haversine filter, sort by (dist, member). Acceptable because `MaxBytes` already caps encoded size (same rationale as zset rebuild-on-mutate). No R-tree/geohash index in v1.

**Encode (canonical):** members sorted by raw member bytes:

```text
for each (member, lon, lat) in member-byte order:
  8 bytes IEEE float64 LE lon
  8 bytes IEEE float64 LE lat
  uvarint(len(member)) + member
```

`EncodeAdd` / `DecodeAdd` pack a single record for fan-out.

### Store

New flags: `FlagGeo` (`1<<10`), `FlagGeoAdd` (`1<<11`), `FlagGeoRem` (`1<<12`).

Under mutex (mirror ModeZSet): live `gCache *geo.Index` + `gDirty` lazy encode; `GeoAdd`/`GeoRem` mutate cache; encode on Peek/Get; protect live geo entries from LRU like Set/ZSet/Bloom.

### Engine

`pkg/engine/geo.go`: mode checks, key/member limits, lon/lat validation, owner local + replicate flags, non-owner ApplyPut, ApplyPut branches, Get/Put reject ModeGeo, GetOrLoadLocal returns FlagGeo snapshot.

### Client / proto / sc

```protobuf
rpc GeoAdd(GeoAddRequest) returns (GeoAddResponse);     // lon, lat, member
rpc GeoRem(GeoRemRequest) returns (GeoRemResponse);
rpc GeoPos(GeoPosRequest) returns (GeoPosResponse);     // present + lon + lat
rpc GeoCard(GeoCardRequest) returns (GeoCardResponse);
rpc GeoDist(GeoDistRequest) returns (GeoDistResponse);  // present + meters
rpc GeoRadius(GeoRadiusRequest) returns (GeoRadiusResponse);
// GeoMember { bytes member; double lon; double lat; double dist_meters }
// GeoRadiusRequest { keyspace, name, lon, lat, radius_meters, limit }
```

**`cmd/sc` (required):**

| CLI | Maps to |
|-----|---------|
| `geoadd <name> <lon> <lat> <member>` | `GeoAdd` |
| `georem <name> <member>` | `GeoRem` |
| `geopos <name> <member>` | `GeoPos` (`lon lat` or `(nil)`) |
| `geocard <name>` | `GeoCard` |
| `geodist <name> <a> <b>` | `GeoDist` (meters, or `(nil)`) |
| `georadius <name> <lon> <lat> <radius_m> [limit]` | `GeoRadius` (lines `dist member lon lat`) |

Session keyspace same as get/put/z*. `set` stays put; no clash.

## Open points (resolved)

1. **Naming:** **ModeGeo** / **Geo\*** (not ModeGeoIndex).
2. **Lat clamp:** **±90** (no public geohash in v1).
3. **GeoRadius `limit`:** **in v1** (`limit <= 0` = all).
4. **Empty after last GeoRem:** keep empty entry (**Card 0**) until `Delete(name)`.

## Rejected alternatives

| Idea | Why not |
|------|---------|
| One KV key per member | No efficient radius; RF multiplies keys |
| Encode lon/lat as ZSet score | Score is 1-D; radius needs 2-D; pollutes ModeZSet |
| Redis 52-bit geohash zset | Ties public API to Redis encoding; still scan or extra index for radius |
| R-tree / H3 dependency | Unnecessary for MaxBytes-bounded v1; scan + haversine is enough |
| Full snapshot LWW every GeoAdd | O(n) network always; item-level matches Set/ZSet |
