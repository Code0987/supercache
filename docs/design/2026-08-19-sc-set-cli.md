# ModeSet CLI (`sc sadd` …)

**Status:** approved  
**Branch:** `feat/sc-set-cli`

Approved in chat (`lets roll` on the parked ModeSet CLI plan).

## Problem

ModeSet shipped engine/proto/client but **no `sc` commands**. README still says use `pkg/client`. ModeSet design required CLI; ZSet later required CLI in-product. Operators cannot add/test tags from the shell without writing Go.

`sc set` is already an **alias for put**. Overloading `sc set add` would break `sc set k v`.

## Non-goals

- New Set RPCs or engine behavior
- Dropping `set` as put alias
- Set algebra (`SUNION` / `SINTER`)
- Changing Get-hit / RF / ModeSet wire flags

## Contract

Keep `set` = put. New Redis-ish verbs (same style as `zadd` / `zcard`):

| CLI | Maps to | Output |
|-----|---------|--------|
| `sadd <name> <item>` | `SetAdd` | `OK sadd <name> <item>` (quiet `-q` silent) |
| `srem <name> <item>` | `SetRemove` | `OK srem …` |
| `sismember <name> <item>` | `SetContains` | `true` / `false`; exit 1 if false |
| `scard <name>` | `SetCard` | integer |
| `smembers <name>` | `SetMembers` | one member per line |

- Session keyspace (`-keyspace` / REPL) same as get/put/z*.
- Empty name/item → usage exit 2 (same as zrem empty-arg).
- Help + `cmd/sc/README.md` updated.
- No proto/engine change.

## Approach

`cmd/sc` dispatch + `main.go` allowed commands + help. Client methods already exist.

Rejected: `sc set add` (clashes with put alias); `sc members add` (ugly).

## Tests (first)

| Test | Package | Asserts |
|------|---------|---------|
| Usage missing args | `cmd/sc` | exit 2, no dial |
| `sadd`/`sismember`/`scard`/`smembers`/`srem` round-trip | `cmd/sc` | against in-process ModeSet server |
| `set k v` still put | `cmd/sc` | `set` not remapped to SetAdd |

## Bench risk

Hot path? No. CLI-only. Get-hit allocs must stay flat. Shared smoke/micro ±10%.
