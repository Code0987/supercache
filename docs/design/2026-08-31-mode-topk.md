# Top-K type (`ModeTopK`) — music plays billboard

**Author:** SuperCache
**Status:** approved
**Branch:** `feat/mode-topk`
**Date:** 2026-08-31

## Overview

SuperCache can count one name (`ModeCounter`), estimate how many distinct items have been seen (`ModeHLL`), and store an exact unbounded scored set you **write scores into** (`ModeZSet`). It cannot answer “which tracks are being played the most right now?” when the catalog is large, the writes are **observations** (a play of `t001`, not an authoritative score), and the product only needs the **names** of the head of the chart.

`ModeTopK` is a **bounded, approximate heavy-hitter filter**. Callers only poke a named sketch with items (`TopKAdd`). Memory is **O(K)** — not O(distinct). `TopKList` returns at most K `(item, count)` rows. v1 is Metwally Space-Saving, stdlib-only, ACK-only, List/HLL-class **snapshot fan-out**. It is **not** Redis `TOPK.*`, not ZINCRBY.

The motivating product **is** [`examples/billboard`](../../examples/billboard/): a kitchen-sink 3-node music cluster. The **live trending-now board** is a play stream (observations, no score) — ModeTopK is the apt type. The **official** global/genre boards stay `LoadThrough` `charts` (precomputed SoT JSON). Time windows go in the **name** (`hot:2026-08-31-15`), the same trick as ModeCounter rate limits — **no decay in v1**. **No** new `examples/topk` package.

This is new product behavior on the data path. Full path in [WORKFLOW.md](../WORKFLOW.md): design → review → (after approval) tests → code → bench → PR. **No tests or implementation until this draft is approved** (`looks good` / `do it` / `implement`).

## Problem

A radio-scale play stream is the wrong shape for every shipped mode.

| Mode | Shape | Why it is not Top-K |
|------|--------|---------------------|
| `ModeZSet` `ZAdd` | Exact, **unbounded** scored set | You **write a score**. The whole zset is **one LRU entry** ([2026-08-13-mode-zset.md](./2026-08-13-mode-zset.md)). 500 distinct tracks already bloat that blob; 10k–100k distinct / day at a station approaches or exceeds `DefaultMaxValueSize` (1 MiB). No `ZINCRBY` in v1. |
| `ModeCounter` | Exact `int64` of **one** name | One sketch per track (`plays:t001`) explodes names and cannot return “the winners” without a client-side scan. |
| `ModeHash` | Field → blob | No increment. `HINCRBY` was rejected: hint coalesce drops increments ([2026-08-20-mode-hash.md](./2026-08-20-mode-hash.md)). |
| `ModeHLL` | Approx **distinct** count | Answers “how many unique tracks were played?” with **no identities**. Cannot name the head. |
| `ModeSet` / `ModeBloom` | Membership | No counts, no ranking. Set is O(distinct). |
| `ModeList` / `ModeJSON` / `ModeBitmap` / `ModeGeo` | Sequence / document / bits / points | Wrong shape. |
| CacheOnly / LoadThrough | Opaque KV | `Put` LWW-replaces a blob. A client-side heap in the value is a lost-update race. |
| PLAN §14 “Hot-key top-K per keyspace \| 1024” | Warmup **tracker** | Internal hot-key sampling for refresh-ahead. **Not** a user-visible chart type. Do not reuse it. |

Count-Min Sketch is **not shipped**. CMS answers “approx count of an item you **name**”; it does not return the winner list unless a second structure (heap) tracks identities.

**Top-K uniqueness (locked):**

- **ZSet** is an exact, unbounded scored set you write scores into.
- **Top-K** is a bounded, approximate heavy-hitter filter you only **poke with items** (observations / +1). Memory is O(K), not O(distinct). Losing the tail is fine. Approximate counts are fine.
- If the candidate set is small **or** scores are authoritative (editorial votes, SoT rank), that is **ZSet** — or a future `ZINCRBY` extension — **not** this mode.

[`examples/billboard`](../../examples/billboard/) is the kitchen-sink cluster (LoadThrough `charts` SoT, stampede, editorial `ModeSet` `tags`, CacheOnly pins, HTTP UI). Today the **live** board is `ModeZSet` `board` with **explicit vote scores** (`handleBoard`, `ZAdd alice/bob/carol`). That is the wrong type for **plays**. This PR **replaces that path with ModeTopK** — not a follow-up, not a second votes board “for contrast.” ZSet remains the type for editorial/authoritative scores (README sentence only). LoadThrough `charts` is **not** a ranking type; keep it.

Two ranking stories (do not collapse them):

| Story | Keyspace | Job | This PR |
|-------|----------|-----|---------|
| Official boards | `LoadThrough` `charts` | Precomputed SoT JSON (`chart:global`, genre boards, track cards, stampede, WarmKeys, invalidate) | **Keep** |
| Live plays / trending-now | **`ModeTopK` `plays`** | Observations: `TopKAdd` per play, `TopKList` ≤ K | **Replace** `ModeZSet` `board` |
| Listener votes with a score | `ModeZSet` | Authoritative `ZAdd(member, score)` | **Remove** from this demo (type stays in the product) |

### Dedicated use case: music plays billboard

A station (or a streaming service’s “trending now” tile) observes plays:

- Catalog: **500 play ids** `t001`–`t500` on the live board; **20** `t01`–`t20` `seedTracks` stay the SoT official-chart catalog ([`catalog.go`](../../examples/billboard/catalog.go)). Radio-station scale: **10k–100k distinct / day**.
- Writes: each play is `TopKAdd(plays, hot, []byte("t001"))`. **No score.**
- Reads: page views call `TopKList` — a chart of length **≤ K** (product default **100**, billboard live board **10** so replace-min is visible).
- Read-heavy: many more chart renders than plays, but play QPS is still the mutate path.
- Replica `TopKList` may lag by **one fan-out RTT**. Acceptable for a chart.
- Hourly / daily windows: **name** `hot:2026-08-31-15`, same as [`examples/ratelimit`](../../examples/ratelimit/) putting the window id in the ModeCounter **name**. No decay. Scripted demo uses **`hot` only**; the window trick is README.

Memory is the product reason:

| Sketch | What is stored | 500 tracks (`t001`, 4 B) | 100k distinct / day |
|--------|----------------|--------------------------|---------------------|
| `ModeZSet` of every play-id | 8 B score + uvarint(len) + member **per distinct** (`pkg/zset.Encode`) | ≈ 500 × (8+1+4) = **6.5 KiB** and **grows without bound** | ≈ 100k × 13 B ≈ **1.24 MiB** — over `DefaultMaxValueSize` (1 MiB) |
| `ModeTopK` K=100 | ≤ K slots of `uvarint(count)+uvarint(len)+item` | ≈ 100 × (1+1+4) = **~600 B** typical | **same ~600 B** (replace-min keeps ≤ K; not every distinct) |
| `ModeTopK` K=100 worst case (item = `MaxKeyLen` 512) | K × (10 + 2 + 512) = **52400** | **~51.2 KiB** fixed cap | **same ~51.2 KiB** |

A 500-track ZSet already “fits.” A station-day does not — and even when it fits, the LRU entry is the **whole** distinct set. Top-K keeps **K slots**. That is the type.

Dedicated example (same implementation PR): **update [`examples/billboard`](../../examples/billboard/)**. **No** new `examples/topk`. Keep the kitchen sink; swap only the live ranking keyspace.

## Goals & Non-Goals

### Goals

- Named, keyspace-scoped Space-Saving table with two verbs + `Delete(name)`.
- O(K) memory regardless of stream cardinality.
- Owner ACK + async `FlagTopK` snapshot to RF−1. No new Peer RPC.
- Present-bit on the **name** (missing ≠ empty list).
- Update [`examples/billboard`](../../examples/billboard/) in the type PR: live board = ModeTopK `plays` (remove ModeZSet `board`).
- Product docs in that same PR (stop saying the billboard uses ModeZSet votes).

- RedisBloom / Redis `TOPK.RESERVE` / `TOPK.ADD` / `TOPK.QUERY` / `TOPK.COUNT` / `TOPK.LIST` / `TOPK.INFO` **numeric or wire parity**. Different algorithm (they use HeavyKeeper). SuperCache verbs are `TopKAdd` / `TopKList`.
- `TopKQuery` / `TopKCount` in v1. Space-Saving can answer a count only for items **in** the table; “not in table” is **not** zero (that would pretend we are CMS). Omit. Keep the surface two verbs + Delete.
- Increment-by-`n` / `TopKIncr` in v1. `TopKAdd` is **+1**. (Inbox could carry `n` without a Peer RPC; still out — do not explode the contract.)
- Per-name `RESERVE` / per-name K. K is keyspace `TopKSize`.
- Decay, sliding windows, or time-weighted scores inside the type. Window id goes in the **name**.
- HeavyKeeper, CMS+heap, Stream-Summary merge, or any non-stdlib sketch.
- Multi-key unions / intersections / merges of two Top-K names (PLAN §1 already excludes multi-key atomicity).
- `ZINCRBY` on ModeZSet (separate design if ever; not a substitute for a bounded filter).
- A new `examples/topk` mini-walkthrough (user wants the real billboard).
- Replacing LoadThrough `charts` with Top-K (official SoT boards are a different job).
- A second live ModeZSet “votes” board in the same PR “for contrast.” README sentence is enough.
- A default `-demo-keyspace` Top-K keyspace on the stock node (same as HLL). Optional follow-up only.
- Changing RF, tombstones, **hint identity** (`hintID` stays `(ks, name)` except `FlagBloomAdd` in `internal/peer/hints.go`), or existing Get/Put/Delete / Bloom / Set / ZSet / Geo / List / Hash / Counter / JSON / Bitmap / HLL contracts.
- Persistence / WAL / Redis dump import.
- scbench YAML cells.
- A new Peer RPC.
- CRDTs, streams.

Top-K as a SuperCache **mode** is in scope. **Do not add Top-K to PLAN §1 non-goals.** Multi-key unions stay out. This is not Redis `TOPK`.

## Why not item-level fan-out (locked)

Two `TopKAdd`s of **different** tracks commute at the algorithm level only in a weak sense (both are increments), but Space-Saving **replace-min** is **not** a commutative OR: the second add can evict the first item if the table is full. Even before that, `hintID` is still `(ks, name)`:

```go
// internal/peer/hints.go
func hintID(ks, key string, ent store.Entry) string {
    if ent.IsBloomAdd() {
        return ks + "\x00" + key + "\x00" + string(ent.Value)
    }
    return ks + "\x00" + key
}
```

A second mutate of the same name **replaces** the pending hint. Item-level `FlagTopKAdd(item)` on the replica **wire** would drop an earlier *other* track — the List / JSON / Bitmap / HLL snapshot reason, and the Hash caveat we refuse ([2026-08-20-mode-hash.md](./2026-08-20-mode-hash.md)). Bloom is the **only** exception because `hintID` includes the item.

**v1 wire:** every owner mutate fans out a **full encoded table** (`FlagTopK`) at the post-op version. Hint coalesce keeps the newest snapshot — that is correct. Network is O(K) per add (typically hundreds of bytes; worst case **52400** bytes at default K=100 and `maxItem=512`).

**No `FlagTopKAdd` on the replica wire.** That flag is **owner-inbox only** (List `FlagListLPush` / `FlagListRPush` in `pkg/engine/list.go`; HLL `FlagHLLAdd` in `pkg/engine/hll.go`; Bitmap `FlagBitmapSet` in `pkg/engine/bitmap.go`).

Rejected for v1: per-item replica apply; hintID change; op-log + snapshot-on-gap; Hash-class item-level with a “do not require both tracks” caveat.

## Contract

### API (new; existing verbs unchanged)

On `pkg/engine.Engine`, `pkg/client.Client`, Cache proto, and **`cmd/sc`** (same PR as the type):

| Call | Meaning |
|------|---------|
| `TopKAdd(ks, name, item []byte)` | Observe `item` once (+1). Creates the table if missing. **ACK-only.** |
| `TopKList(ks, name) (entries []TopKEntry, ok bool, err)` | Current chart. Missing **name** → `ok=false`, `entries=nil`. Live table after first add (including occupied &lt; K) → `ok=true`. Sorted **count desc**, then **item bytes** ascending. Length ≤ K. |
| `Delete(ks, name)` | Existing Delete: whole-table tombstone. |

```go
type TopKEntry struct {
    Item  []byte
    Count uint64
}

TopKAdd(ctx context.Context, keyspace, name string, item []byte) error
TopKList(ctx context.Context, keyspace, name string) (entries []TopKEntry, ok bool, err error)
```

- `name` is the sketch identity; ring owner = `Owner(name)`. Validated with `validateKey` + `validateKeyLen` (per-keyspace `MaxKeyLen` applies to **name**).
- `item` is `[]byte`. **Empty item → `ErrInvalidArgument`** (`empty topk item`), same as List / Bloom / Set / HLL. Items **are stored** (unlike HLL, which hashes and forgets), so the item bound is the same as `validateKeyLen` (`pkg/engine/engine.go`): `ks.MaxKeyLen` if set, else `e.maxKeyLen`. `len(item) > that max` → `ErrKeyTooLarge`. Inbox `applyTopKAdd` uses the same max (reject `applied=false`). This is **stricter than** Bloom / List / HLL, which compare the item only to `e.maxKeyLen`.
- `TopKAdd` is ACK-only. It does **not** return the new count, whether the item entered the table, or whether a min was evicted. A return payload would need a new Peer RPC. Do not add one.
- Each **owner** `TopKAdd` that applies assigns a **new stored version under the store mutex** (JSON/Bitmap/HLL/List/Counter rule — [2026-08-25-list-counter-version.md](./2026-08-25-list-counter-version.md)) and refreshes whole-name `ExpireAt` from keyspace `TTL` (`0` = none) — scheme B / Hash / List / Counter / JSON / Bitmap / HLL. ApplyPut paths use inbound `expireAt`, or `e.expireAt(TTL)` when the wire value is `0`. The inbound ApplyPut `Version: 1` on inbox flags is **not** the stored snapshot version.
- `TopKAdd` of an item already in the table **still** applies: count+1, new version, TTL slide, snapshot fan-out (a touch). Same as `HLLAdd` of an already-seen item / `BitSet` of an already-set bit / `Incr(0)`.
- `TopKAdd` that would overflow `uint64` — increment of a resident slot at `MaxUint64`, **or** replace-min when `occupied == K` and `min.count == MaxUint64` — → `ErrInvalidArgument`, **no wrap**, table unchanged (Counter rule).
- Get/Put on `ModeTopK` → `ErrInvalidArgument` (`use TopKList` / `use TopKAdd`).
- TopK* on non-`ModeTopK` → `ErrInvalidArgument`.
- Cross-mode misuse (TopKAdd on ModeHLL, HLLAdd on ModeTopK, ZAdd on ModeTopK, …) → `ErrInvalidArgument`.

**Not in v1:** `TopKQuery`, `TopKCount`, `TopKIncr`, per-name K, decay, Redis TOPK names.

### Present-bit vs Redis empty list (locked)

Redis `TOPK.LIST` of a missing key is an error / empty depending on module version. SuperCache keeps a **present-bit** on name identity, matching Hash / List / Counter / JSON / Bitmap `BitGet` / HLL `HLLCount`:

| State | `HasTopK` | `TopKList` |
|-------|-----------|------------|
| Missing name / expired / tombstone | false | `entries=nil`, **`ok=false`**, nil error |
| Live table after first add (occupied 1..K) | **true** | sorted rows, **`ok=true`** |
| Live table, occupied &lt; K (“empty-ish”) | **true** | the occupied rows, **`ok=true`** |
| Live encoded-empty blob (install only; owner never produces one) | **true** | empty slice, **`ok=true`** |

A live Top-K stays **present** until `Delete(name)`. `sc topklist` prints one `item count` line per row when `ok=true`, `(nil)` + exit 1 when `ok=false` (copy `cget` / `hllcount`). `ok=true` with zero rows prints nothing and exits 0 — distinct from miss.

Do **not** return `ErrUnavailable` on `TopKList`. Owner-down / `GetOrLoad` failure / `!Found` / `!IsTopK` → miss (`ok=false`, `entries=nil`, nil error). Same as `hllFetchOwner` / `bFetchOwner`.

### Empty-until-delete (locked)

Prefer empty-until-delete (same spirit as Hash / List / Counter / JSON / Bitmap / HLL):

| Op | Result |
|----|--------|
| First `TopKAdd` of a missing name | **Creates** a table with that item at count 1; `HasTopK` true |
| `TopKAdd` of an already-tracked item | Stays live; count+1; new version + TTL slide |
| `TopKAdd` of a new item when occupied &lt; K | Insert count 1 |
| `TopKAdd` of a new item when full | Replace the min-count slot (tie: smallest item bytes); new count = min+1. If `min.count == MaxUint64` → reject, no wrap |
| There is no “TopK create empty” / “TopK clear” verb | First add creates; `Delete(name)` is the only drop |
| `TopKAdd` never calls `Delete(name)` | Adding is not a tombstone |

### Size / DoS (locked)

The stored blob is **at most K slots**. One formula, one number:

```go
// topkx.WorstEncodedSize — count uvarint worst-case is MaxVarintLen64 (10).
func WorstEncodedSize(k, maxItem int) int {
    if k < 1 || maxItem < 0 {
        return 0
    }
    return k * (10 + uvarintSize(uint64(maxItem)) + maxItem)
}
// Default K=100, maxItem=512: uvarint(512)=2 → 100*(10+2+512) = 52400
```

Typical music ids (`t001`, 4 bytes, small counts): ~6 B/slot × 100 ≈ **600 B**.

```text
K       = ks.EffectiveTopKSize()                         // 0 → 100
max     = ks.MaxValueSize > 0 ? ks.MaxValueSize : e.maxValueSize
maxItem = itemMax(ks)   // engine: ks.MaxKeyLen if > 0 else e.maxKeyLen
                        // Validate: MaxKeyLen if > 0 else DefaultMaxKeyLen (512)
if max > 0 && topkx.WorstEncodedSize(K, maxItem) > max  → ErrValueTooLarge, no mutate
```

- **Initiating node** rejects `TopKAdd` when worst-case &gt; `max` **before** apply or `ApplyPut` forward (so clustered clients get `ErrValueTooLarge`, not a swallowed `!applied`).
- Owner `TopKAdd` also checks; `tooLarge=true`, **no mutate**. After encode, `len(blob) > max` is the same (`tooLarge`).
- Inbox apply that still overflows (race on `MaxValueSize`, corrupt inbox) → `applied=false`. ACK-only `ApplyPut` cannot carry `ErrValueTooLarge`; the non-owner maps `!applied` to `ErrInvalidArgument` (`topk add rejected`). Owner-hit / single-node path **does** return `ErrValueTooLarge`.
- `UpdateKeySpace` / `Config.Validate` (`pkg/keyspace/config.go` — no engine pointer): `ModeTopK` and `WorstEncodedSize(EffectiveTopKSize(), maxItem) > effectiveMaxValue` **fails validation**. `maxItem = MaxKeyLen` if `MaxKeyLen > 0`, else **`DefaultMaxKeyLen` (512)**. `effectiveMaxValue` is `MaxValueSize` if set, else `DefaultMaxValueSize` (1 MiB), so a huge `TopKSize` fails fast even when `MaxValueSize` is 0.
- `TopKSize < 0` → Validate error. `TopKSize == 0` → default 100. When set, `TopKSize ≥ 1`.
- **Shrinking `TopKSize` under a live name is an operator foot-gun.** A live blob with `occupied > new K` fails `Decode(..., k)` (see store `TopKAdd`). **`Delete(name)` first**, then `UpdateKeySpace`. Do not truncate.
- `MaxBytes` may still **overshoot** one live `FlagTopK` (same as Set/Geo/List/Hash/JSON/Bitmap/HLL). Do **not** fail `Validate` when `MaxBytes < table_worst`.
- Incoming snapshot: decode error, duplicate item, count==0, empty item, or `occupied > K` → `TopKInstall` rejects (`applied=false`). No truncate, no pad, no silent drop of extra slots.

Item DoS is the `validateKeyLen` cap on the stored item plus the blob bound.

### Keyspace

New mode `keyspace.ModeTopK` (next iota after `ModeHLL`). `Mode.String()` **must** return `"TopK"` (else `/keyspaces` prints `Mode(12)`).

Current iota (`pkg/keyspace/config.go`): `LoadThrough=0` … `ModeHLL=11`. `ModeTopK=12`.

| Field | Role |
|-------|------|
| `MaxBytes` | Cost budget. Live `FlagTopK` is LRU-protected; one table may **overshoot** |
| `TTL` | Expires the **whole** name; owner `TopKAdd` **slides** `ExpireAt` (scheme B) |
| `NegativeTTL` | Ignored |
| `TombstoneTTL` | On `Delete(name)` |
| `ReplicationFactor` | Same as KV / ModeHLL |
| `MaxKeyLen` | Bounds `name` **and** the stored **item** (`validateKeyLen` max: `MaxKeyLen` if set, else engine `maxKeyLen`) |
| `MaxValueSize` | Bounds the **encoded table**. Must fit `WorstEncodedSize(K, maxItem)` |
| **`TopKSize`** | K. **0 → default 100** (billboard-sized). Per-name RESERVE is not v1 |

```go
const DefaultTopKSize = 100

func (c Config) EffectiveTopKSize() int {
    if c.TopKSize <= 0 {
        return DefaultTopKSize
    }
    return c.TopKSize
}
```

`ConfigHash` **must** include `TopKSize` (same `wire` struct in `pkg/keyspace/config.go` as `BloomBits`). Non-`ModeTopK` keyspaces may set the field; it is ignored except for the hash.

Do not reuse `BloomBits` as K.

### Replication (locked: snapshot like List / JSON / Bitmap / HLL)

| Hop | Payload |
|-----|---------|
| Client → any node → **owner** | `ApplyPut` `FlagTopKAdd` (raw item bytes) if this node is not owner |
| Owner → **replicas** | `FlagTopK` full snapshot after the op (encoded ≤K slots + version + expire) |
| Handoff / `GetOrLoad` | `FlagTopK` install if incoming version **>** local (equal = ignore; tombstone blocks if incoming ≤ tombstone). **Not** a merge of two Space-Saving tables. |

`TopKAdd` is ACK-only — **no new Peer RPC**. Inbox flags + snapshot fan-out (HLL / List **push** / JSON `JsonSet` / Bitmap `BitSet` pattern). `TopKList` never needs a Peer RPC: local extract or `GetOrLoad`.

**Version assignment (locked — one rule for store `TopKAdd`):**

Assign the stored snapshot version **inside the store mutex**. There is **no** second version space (`topkNextVersion` / `max(local, incoming)+1` is **not** used).

```text
if missing / expired (no live entry):     stored = 1          // create
if live FlagTopK or replacing tombstone:  stored = local.Version + 1
incoming `version` argument:              tombstone-gate floor only
                                          (reject if live tombstone && incoming <= tombstone.Version)
```

- Do **not** write the engine’s pre-lock `PeekVersion+1` as `Entry.Version`.
- Engine fans out **`PeekVersion` after the store write** (then `observeVersion` that same value). Never fan out the candidate passed in.
- Concurrent owner `TopKAdd`s serialize on the store mutex → distinct versions → `TopKInstall` (`incoming > local`, equal = ignore — same as `HLLInstall` / `BInstall` / `JInstall` at `pkg/store/memory.go`) cannot drop the later snapshot.

**Owner-inbox vs replica-apply (locked — copy HLL / List / JSON / Bitmap, not Hash / Bloom):**

- Non-owner: `Transport.ApplyPut` `{Flags: FlagTopKAdd, Value: item bytes, Version: 1}`.
- Owner `ApplyPut` of that flag: **apply the op** (store `TopKAdd` first). Pass `PeekVersion+1` (0→1 if missing) **only** as the tombstone-gate floor. Do **not** use inbound `Version: 1` as the stored version. If the store reports a mutate, `ver, _ := PeekVersion(name)` then `ks.observeVersion(name, ver)` + `topkReplicateSnapshot(..., ver, ...)`.
- Replica `ApplyPut` of `FlagTopKAdd`: **ignore** (`return false, nil`) if this node is not owner — same guard as `IsHLLAdd` / `IsListLPush` / `IsJSONSet` / `IsBitmapSet` in `pkg/engine/engine.go` `ApplyPutWithRingGen`. Do not send inbox flags to replicas.
- `FlagTopK` → `TopKInstall` version gate only.

**Owner-local `TopKAdd`:** same as inbox apply — store first, fan out `PeekVersion` after write.

**Non-owner `applied=false`:** initiating node already rejected empty / oversize **item** and worst-case table &gt; max. Owner reject (tombstone, non-TopK entry, overflow) surfaces as `ErrInvalidArgument` (`topk add rejected`). Encoded `ErrValueTooLarge` is guaranteed on the **owner-hit / single-node** path.

**Reads (locked: same as `hllFetchOwner` / `bFetchOwner` / `jFetchOwner`):**

- If `HasTopK` local → extract `TopKList` from the **local** blob. Replica snapshot may **lag by one fan-out RTT**. **Do not** owner-forward a local hit. Acceptable for a chart.
- Else if this node is owner → missing table → `ok=false`.
- Else → `topkFetchOwner` (copy of `hllFetchOwner`):
  - `GetOrLoad` RPC error / owner down / `!Found` / `!IsTopK` → **miss** (`ok=false`, nil error). Do **not** return `ErrUnavailable` on reads.
  - `holdsReplica` → `TopKInstall` then list.
  - Non-replica → decode `ent.Value` in process; **do not** `TopKInstall`.

Owner down on `TopKAdd` → `ErrUnavailable` (no ACK authority), same as Put / HLLAdd / BitSet / JsonSet. Do not apply locally.

```mermaid
sequenceDiagram
  participant C as Client
  participant N as Non-owner
  participant O as Owner
  participant R as Replica
  C->>N: TopKAdd(hot, t001)
  N->>O: ApplyPut FlagTopKAdd inbox Version=1
  O->>O: TopKAdd (stored=local+1 under mutex) + PeekVersion + replicate FlagTopK
  O->>R: ApplyPut FlagTopK snapshot
  O-->>N: applied
  N-->>C: OK
  Note over R: TopKInstall only; ignore inbox flags
  C->>R: TopKList(hot)
  Note over R: HasTopK → local chart (may lag one RTT)
  C->>N: TopKList(hot)
  alt N holds replica copy
    N-->>C: local chart
  else non-replica
    N->>O: GetOrLoad(hot)
    O-->>N: FlagTopK snapshot
    N-->>C: decode List
  end
```

**Hint-after-down (normative):** two `TopKAdd`s of **different** tracks while replica B’s Peer is down; then start B and wait for hint flush. The pending hint is the **latest snapshot** → B’s table contains **both** tracks. Copy HLL/List/JSON/Bitmap ring/transport/down setup (`TestHLLHintAfterPeerDownKeepsBothItems` / `TestListHintAfterPeerDownKeepsBothPushes` / `TestJSONHintAfterPeerDownKeepsBothPaths` / `TestBitmapHintAfterPeerDownKeepsBothBits`). **Do** require both items (this is why we chose snapshot). **Do not** copy Hash’s “do not require both fields.”

Because K ≥ 2 in that test (use default 100 or explicit 10), both adds fit without eviction:

1. After flush, `engB.TopKList` contains **both** original items (and matches `engA` as a set of items).
2. Optional stronger check: `Peek` `Value` bytes equal on A and B (encode is canonical — count desc, then item bytes).

A third `TopKAdd` “to poke the pool” is allowed only if the assert still requires **both original tracks**, not only the poke.

### Handoff is LWW, not merge (locked)

Merging two Space-Saving tables is **not** a well-defined LWW operation. Summing counts double-counts; taking per-item max resurrects a name the owner had already replaced after Delete+recreate; concatenating heaps can exceed K and invent a chart the owner never had.

Two concurrent writers on the **same name** serialize on the owner store mutex, so snapshots are **total-ordered**. Incoming `FlagTopK` with `version > local` **replaces** the blob (`TopKInstall`). Equal = ignore. Tombstone `<=` blocks. This is `HLLInstall` / `BInstall` / `JInstall`, **not** Bloom `BloomMerge`.

Do **not** merge incoming snapshots. A delayed lower-version table must not resurrect tracks a later `Delete`+recreate (or a later owner generation) replaced.

### What existing clients can assume

- CacheOnly / LoadThrough / Bloom / Set / ZSet / Geo / List / Hash / Counter / JSON / Bitmap / HLL unchanged if they never open `ModeTopK`.
- Stock `-demo-keyspace` still registers `board` as ModeZSet (node defaults unchanged). Billboard **cluster** drops `board` and adds `plays`.
- [`examples/billboard`](../../examples/billboard/) **does** change: live board is ModeTopK plays. LoadThrough `charts` / tags / pins / stampede stay.
- Rolling: do **not** register a `ModeTopK` keyspace until every node has the TopK `ApplyPut` branches. An old node would fall through `ApplyPutWithRingGen` to `AcceptIfNewer` and treat `Mode=12` as KV.

## Approach

### Algorithm (locked — Space-Saving, stdlib-only, not Redis-numeric-compat)

Package **`pkg/topkx`** (matches `pkg/jsonx` / `pkg/listx` / `pkg/hllx` / `pkg/bitmapx`).

Cite: Metwally, Agrawal, El Abbadi, *[Efficient Computation of Frequent and Top-k Elements in Data Streams](https://www.cse.ust.hk/~raywong/comp5331/References/EfficientComputationOfFrequentAndTop-kElementsInDataStreams.pdf)* (ICDT 2005; also VLDB Journal 2006) — **normative**. Wikipedia [Streaming algorithm — Heavy hitters / Stream Summary](https://en.wikipedia.org/wiki/Streaming_algorithm#Heavy_hitters) is background only. Do **not** cite the Count–Min Sketch page as Space-Saving. RedisBloom `TOPK` is **HeavyKeeper** — different algorithm, **do not** lock Redis numbers.

**Why Space-Saving for music plays (locked):** play streams are **Zipf** — a few hits, a long tail. Space-Saving keeps K counters and **overestimates** (a new item inherits `min+1`). Replace-min evicts the current **minimum slot**, not “the tail.” After a head-then-tail dump the guaranteed heavy hitters (true count &gt; N/K) stay; mid-head items below that threshold can leave; vacated slots fill with **recent** 1-play ids whose estimates are ~N/K. That is the billboard lesson vs ZSet (which would still store all 500). Tests lock **invariants** and the example’s exact `List()`, not Redis `TOPK.LIST` counts.

```text
Add(item):                                  // +1 only
  if item in table:
      if count == MaxUint64: reject         // no wrap
      count++
      return
  if occupied < K:
      insert (item, 1)
      return
  min = slot with smallest count;
        tie → smallest item bytes           // deterministic
  if min.count == MaxUint64: reject         // no wrap on replace-min
  replace min with (item, min.count+1)
```

Guarantees tests may cite but need not compute N:

- `|table| ≤ K` always.
- If an item is in the table and never left it after an empty-slot insert, `count == true count`.
- If an item entered via replace-min, `count ≥ true count` (overestimate).
- Any item with true count &gt; N/K is in the table (classic Space-Saving). The locked example has N = 1220, K = 10, N/K = 122 → only `t001` (200) and `t002` (150) are guaranteed.

**No heap in v1.** K default 100: linear scan for lookup and min is enough. `slots []Entry` plus optional `map[string]int` is an implementation detail; do not expose it.

```go
package topkx

var (
    ErrEmpty    = errors.New("topkx: empty item")
    ErrK        = errors.New("topkx: K must be >= 1")
    ErrOverflow = errors.New("topkx: count overflow")
    ErrDecode   = errors.New("topkx: bad table blob")
)

type Entry struct {
    Item  []byte
    Count uint64
}

type Table struct {
    k     int
    slots []Entry // occupied only
}

func New(k int) *Table                    // k < 1 → nil; caller validates
func (t *Table) Add(item []byte) error    // ErrEmpty / ErrOverflow
func (t *Table) List() []Entry            // copy, count desc then item bytes
func (t *Table) Occupied() int
func (t *Table) Encode() []byte           // canonical order = List() order
func Decode(b []byte, k int) (*Table, error) // k < 1 → ErrK; bad blob → ErrDecode
func WorstEncodedSize(k, maxItem int) int    // k*(10 + uvarintSize(maxItem) + maxItem)
```

`Table.Count(item)` / point query is **not** part of the engine API. A package-internal helper for algorithm tests is allowed; do not add `TopKQuery`.

**Encoding (locked — occupied slots only, canonical order):**

```text
// repeat occupied times (0 times = empty blob, valid decode)
uvarint(count) uvarint(len) item[len]
```

- Encode writes slots in **List order** (count desc, then `bytes.Compare` item). Replica `Peek` bytes can be compared in tests.
- `count == 0` or `len == 0` on decode → error.
- Duplicate items → error.
- `k < 1` → `ErrK` (this is the only use of `ErrK`; `New` returns nil).
- `occupied > k` → `ErrDecode` (config drift / shrink-K / corrupt). Occupied &lt; K is the normal filling table.
- Empty blob → 0 slots, valid. Owner `TopKAdd` never produces one.

No header, no K in the blob (K is keyspace config). No float scores.

### Store (`pkg/store`)

Last shipped bits in `pkg/store/entry.go`: `FlagHLL` `1<<25`, `FlagHLLAdd` `1<<26`. Next free is `1<<27`:

```go
FlagTopK    uint32 = 1 << 27 // value is encoded Space-Saving snapshot
FlagTopKAdd uint32 = 1 << 28 // owner-inbox: raw item bytes
```

`Entry.IsTopK()` / `IsTopKAdd()`.

**No `topkCache` / `topkDirty`.** The live structure **is** `Entry.Value` (like HLL / Bitmap / Counter / Bloom, unlike JSON/List/Hash). Under the store mutex: decode → `Table.Add` → `Encode` into `Value`. **Do not** add `flushTopKValueLocked` — a Get/Peek helper that is easy to get wrong on the KV hot path. Peek/Get already clone `Value`. A decoded cache is a follow-up only if it never hooks Get/Peek.

```go
// store.Store
TopKAdd(key string, item []byte, version uint64, expireAt int64, k int, maxValue int) (applied, tooLarge bool)
TopKList(key string) (entries []topkx.Entry, ok bool)
HasTopK(key string) bool // live unexpired FlagTopK
TopKInstall(key string, blob []byte, version uint64, expireAt int64, k int) bool // incoming > local
```

**`TopKAdd` (locked).** Gate first; **only a successful apply mutates**.

1. Live non-TopK → `applied=false`; no write.
2. Live unexpired tombstone and `version <=` tombstone → `applied=false`; no write.
3. `k < 1` or worst-case / post-encode `len > maxValue` (when `maxValue > 0`) → `tooLarge=true`, `applied=false` (**before** commit).
4. Missing / expired / tombstone with `version >` tombstone → **create**: `topkx.New(k)` + `Add`. `Add` error (empty item) → `applied=false`, `tooLarge=false`, no insert. Else `Version=1` (or `tombstone.Version+1` when replacing a tombstone), `Flags=FlagTopK`.
5. Live TopK: decode `it.entry.Value` with current `k`. **Decode error or `occupied > k`** (corrupt blob, or `UpdateKeySpace` shrank `TopKSize`) → `applied=false`, `tooLarge=false`, **no mutate, no recreate, no truncate**. Previous bytes and cost unchanged. `HasTopK` stays true (flag gate).
6. Live decode OK: `Add`. **Any `Add` error** (`ErrEmpty`, `ErrOverflow`, …) → `applied=false`, `tooLarge=false`, previous bytes **and cost** unchanged. Else re-encode.
7. Commit under this mutex: `Version = 1` on create (missing/expired) or `local.Version+1` when replacing live TopK / a superseded tombstone; `Flags=FlagTopK`; slide `ExpireAt` if `expireAt != 0`; cost; `MoveToFront`; `evictLocked`. Incoming `version` is **not** written (tombstone-gate floor only — step 2).
8. An add that does not change membership (count+1 of a resident item) **still** commits (version + TTL). There is no “unchanged → skip” path.

**`HasTopK` (locked):** copy `HasHLL` / `HasBitmap` **flag** gate — live, unexpired, not tombstone, `IsTopK`. Do **not** require `len(Value) > 0` and do **not** require `Occupied > 0`.

**`TopKList`:** `HasTopK` + decode + `List()`. Missing → `ok=false`, nil entries. Decode error on a live blob → treat as miss (`ok=false`) and do not panic.

**`TopKInstall`:** same gate as `HLLInstall` / `BInstall` / `JInstall` (`incoming > local`; equal ignore; tombstone `<=` blocks). `Decode(blob, k)` must succeed. Replace with a **copy** of `blob` (do not re-encode). Reject `occupied > k`.

**Stored version (locked):**

```text
stored = local.Version+1          // live FlagTopK, or replace tombstone after gate
stored = 1                        // TopKAdd create (missing / expired; no local entry)
incoming version                  // tombstone-gate floor only
```

Engine **must** replicate `PeekVersion` **after** `TopKAdd` returns applied, not the candidate it passed in. `observeVersion` that same post-write version.

Protect live `FlagTopK` in `lruVictim` (`pkg/store/memory.go` today lists Bloom/Set/ZSet/Geo/List/Hash/Counter/JSON/Bitmap/HLL).

`Set` / `AcceptIfNewer` need no TopK cache to clear.

```go
func (e *Engine) itemMax(ks *ksRuntime) int {
    max := e.maxKeyLen
    if ks.cfg.MaxKeyLen > 0 {
        max = ks.cfg.MaxKeyLen
    }
    return max
}

func (e *Engine) applyTopKAdd(ks *ksRuntime, name string, item []byte, expireAt int64) bool {
    if len(item) == 0 || len(item) > e.itemMax(ks) {
        return false
    }
    if expireAt == 0 {
        expireAt = e.expireAt(ks.cfg.TTL)
    }
    max := e.maxValueSize
    if ks.cfg.MaxValueSize > 0 {
        max = ks.cfg.MaxValueSize
    }
    k := ks.cfg.EffectiveTopKSize()
    cur, _ := ks.store.PeekVersion(name)
    gate := cur + 1 // tombstone floor only; store assigns the stored version
    ok, tooLarge := ks.store.TopKAdd(name, item, gate, expireAt, k, max)
    if !ok || tooLarge {
        return false
    }
    ver, _ := ks.store.PeekVersion(name)
    ks.observeVersion(name, ver)
    e.topkReplicateSnapshot(ks, name, ver, expireAt)
    return true
}
```

## Data model / migration

No on-disk format. No migration. New `Mode` iota and two `Entry` flags. Rolling: deploy the build cluster-wide, **then** `UpdateKeySpace` a `ModeTopK` keyspace. Old nodes would treat `Mode=12` as KV if a TopK keyspace were registered early — forbidden in the rollout.

`ConfigHash` gains `TopKSize`; `/peers` drift detection will flag mixed configs (already unsupported in v1).

`UpdateKeySpace` may shrink `TopKSize` on a live name. The stored blob is not rewritten. Next `TopKAdd` / `TopKInstall` / `TopKList` decode with the new K: `occupied > k` fails. Mutates **do not** recreate or truncate (store steps 5–6). **Delete the name before shrinking K.**

## Security & privacy

No new auth surface. Document names/items ride the existing Cache gRPC (TLS) and Peer ApplyPut (mTLS). Do not log item bodies or table blobs (track ids are mild; the same API will be used for user ids). Limits (`validateKeyLen` on name **and** stored item; `WorstEncodedSize` vs `MaxValueSize`; `MaxBytes` may overshoot one live TopK) are the DoS bound — the bomb is “many names” or “huge K”, both fail Validate.

Owner **store mutex** serializes `TopKAdd` **and** assigns `stored = local.Version+1` (or `1` on create). There is **no** extra engine owner-mutate mutex — same as Hash/List/JSON/Bitmap/HLL. Two clients mutating the same name apply in store-lock order; successive snapshots have distinct versions so `TopKInstall` cannot drop the later one. A client that retries `TopKAdd` after a timeout may double-apply (a play counted twice). SuperCache does not have request ids. Do not use `TopKList` counts as an exact royalty ledger.

## Observability

Reuse existing fan-out / hint / `staleSkip` / store hit-miss counters. No new required metrics in v1. Optional later: occupied/K histogram, replace-min rate. Wrong-mode, empty item, and oversize map through `grpcmap`.

## Rollout / rollback

- Opt-in: nothing happens until an operator registers a `ModeTopK` keyspace on **every** node.
- Deploy the TopK build cluster-wide first; then `UpdateKeySpace`.
- Rollback: stop writing TopKAdd; `Delete(name)` or drop the keyspace. No on-disk format.
- No feature flag (mode is the flag).
- Billboard example is in-process only; it does **not** change stock `-demo-keyspace`.
- [`examples/billboard`](../../examples/billboard/) **is** the ModeTopK demo (live `plays`). Official `charts` SoT is unchanged.

## Rejected alternatives

| Idea | Why not |
|------|---------|
| `ZINCRBY` on ModeZSet | Exact, unbounded, one LRU blob of **all** distinct; ZAdd already requires a score ([mode-zset](./2026-08-13-mode-zset.md)); not a filter |
| CMS-only | Point query of a name you already have; no winner list |
| Client-side heap in a KV blob | Lost-update on Put; no owner serialize |
| Item-level `FlagTopKAdd` to replicas | Lost hints drop the other track; `hintID` is `(ks, name)` |
| HeavyKeeper / RedisBloom TOPK v1 | Extra surface; we refuse numeric parity anyway |
| Decay / sliding window in the type | Window id belongs in the **name** (`examples/ratelimit`) |
| Per-name K / `RESERVE` | One `TopKSize` keeps Validate / install size trivial |
| Merge-on-handoff of two tables | Not LWW-safe after Delete+recreate |
| Separate `examples/topk` mini-walkthrough | User wants the real billboard; kitchen sink already has HTTP/UI/cluster |
| Replace LoadThrough `charts` with TopK | Official SoT boards are a precomputed JSON blob, not a play stream |
| Keep ModeZSet `board` votes “for contrast” | User said use Top-K **instead**. README sentence vs ZSet is enough |
| CRDT / G-counter per item | PLAN §1 forbids CRDTs; memory would be O(distinct) |
| Streams | PLAN §1 non-goal |
| `TopKQuery` / `TopKCount` in v1 | “Not in table ≠ 0”; would fake CMS |
| `TopKIncr(n)` in v1 | Can be inbox-only later; +1 keeps the first PR small |
| Bloom-style hintID `(ks, name, item)` | Touches global hint path; Bloom is the documented exception |
| Hash-class item-level + “don’t require both tracks” | Accepts silent data loss; we can snapshot O(K) instead |
| Change hintID in this PR | Touches global hint path; separate design |
| Client-built snapshot ApplyPut to owner | Two writers clobber; owner must apply the **op** |
| New Peer RPC / return count-or-evicted | TopKAdd is ACK-only; ApplyPut suffices |
| Default TopK demo keyspace | Same as HLL; example starts its own mesh |
| `TopKAdd` pre-lock nextVersion as stored | Two version spaces; replica `TopKInstall` can drop the later snapshot |
| Peek/Get `flushTopK*` helper | Unnecessary (Value is encoded) and a Get-hit alloc risk |
| Names `ModeHeavyHitters` / Redis `TOPK.ADD` | Breaks Geo/Hash/HLL short-name convention |
| Reuse warmup hot-key tracker | Different feature (PLAN §14, 1024 keys, not a chart) |
