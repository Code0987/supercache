# HLL type (`ModeHLL`)

**Status:** approved  
**Branch (later):** `feat/mode-hll`  
**Date:** 2026-08-25

## Problem

SuperCache has no **approximate distinct cardinality** type. Callers who want “how many unique items have we seen?” today abuse a wrong mode:

| Mode | Shape | Why it is not HLL |
|------|--------|-------------------|
| `ModeSet` `SetCard` | Exact membership | Stores **every** member. Memory is O(n). That is the exact set, not a sketch. |
| `ModeCounter` | One `int64` | Increments a scalar. Not distinct: two adds of the same item count as two. |
| `ModeBloom` | Fixed-size probabilistic filter | Answers **membership** (`BloomTest`) with false positives. It does not estimate cardinality. OR-merge of bitsets is the opposite of LWW snapshot. |
| `ModeBitmap` `BitCount` | Packed addressable bit vector | Counts **set bits** in a dense Redis-order string (`pkg/bitmapx.Count`). Offset *n* is a bit address, not a hashed item. |
| `ModeZSet` `ZCard` | Scored members | Exact members, O(n) memory. |
| CacheOnly / LoadThrough / `ModeHash` / `ModeJSON` / `ModeList` / `ModeGeo` | KV / fields / document / sequence / points | Wrong shape. `Put` LWW-replaces a blob. |

HLL is the first **approximate distinct count of hashed items** in a tiny **fixed register array**. One named sketch, ~12 KiB, standard error ≈ `1.04/√m` ≈ 0.81% at Redis-class `p=14`. That is the type Set / Counter / Bloom / Bitmap cannot express.

`Get`/`Put` cannot express it. `Get` returns a blob; `Put` replaces a blob. A sketch has a **name** plus an **item** to hash. Mapping `Put(name, item)` would overload Put and still have no `Count`.

This is new product behavior on the data path. Full path in [WORKFLOW.md](../WORKFLOW.md): design → review → (after approval) tests → code → bench → PR. **No tests or implementation until this draft is approved** (`looks good` / `do it` / `implement`).

### PLAN §1 is not a fight (locked)

PLAN §1 non-goals include the line:

> Full Redis protocol; streams, HyperLogLog, multi-key ZUNION/ZINTER

That sentence is about **not speaking RESP** and **not cloning Redis** as a product. It is the same class of “we are not Redis” as streams and multi-key `ZUNION`. A SuperCache **mode** named HLL is allowed — Bitmap and JSON were also absent from the original “structured types” sentence and shipped as SuperCache modes. **Do not invent a §1 fight.** `PFMERGE` stays out because it is multi-key (PLAN §1 already excludes multi-key atomicity). The mode is `ModeHLL`, the verbs are `HLLAdd` / `HLLCount`, and estimates **will not** match Redis `PFCOUNT` on the same items.

## Non-goals

- Redis `PFMERGE` (multi-key; PLAN §1 already excludes multi-key atomicity)
- Redis `PFADD` return-was-changed (`1` if the sketch changed). That needs a Peer RPC (`ListPop` / `CounterIncr` class). `HLLAdd` is **ACK-only**
- Redis RDB / dump byte-compat (`HYLL` header, sparse encoding, MurmurHash64A). SuperCache has no persistence and no Redis import
- Configurable precision as a keyspace knob (`HLLPrecision` / `p`). v1 locks Redis-class `p=14`
- Redis sparse encoding (first add would stay tiny). v1 is dense-only: first add allocates 12 KiB
- Per-item delete / “un-add” (classic HLL cannot)
- Per-item TTL inside a sketch
- Changing RF, tombstones, **hint identity** (`hintID` stays `(ks, name)` except `FlagBloomAdd` in `internal/peer/hints.go`), or existing Get/Put/Delete / Bloom / Set / ZSet / Geo / List / Hash / Counter / JSON / Bitmap contracts
- Persistence across process restart
- A new default `-demo-keyspace` HLL keyspace (`flags` just shipped ModeBitmap)
- scbench YAML cells
- A new Peer RPC (`HLLAdd` is ACK-only; `HLLCount` is extract / `GetOrLoad`)
- Matching Redis `PFCOUNT` numerically (different hash + no Redis bias tables)

HLL as a SuperCache **mode** is in scope. Do not add HLL to §1 non-goals.

## Why not item-level fan-out (locked)

Two `HLLAdd`s of **different** items commute at the register level (per-register `max`), but `hintID` is still `(ks, name)`:

```go
// internal/peer/hints.go
func hintID(ks, key string, ent store.Entry) string {
    if ent.IsBloomAdd() {
        return ks + "\x00" + key + "\x00" + string(ent.Value)
    }
    return ks + "\x00" + key
}
```

A second mutate of the same name **replaces** the pending hint. Item-level `FlagHLLAdd(item)` on the replica **wire** would drop an earlier *other* item — the List / JSON / Bitmap snapshot reason, and the Hash caveat we refuse ([2026-08-20-mode-hash.md](./2026-08-20-mode-hash.md)). Bloom is the **only** exception because `hintID` includes the item.

**v1 wire:** every owner mutate fans out a **full dense register blob** (`FlagHLL` `1<<25`) at the post-op version. Hint coalesce keeps the newest snapshot — that is correct. Network is a fixed 12 KiB per add.

**No `FlagHLLAdd` on the replica wire.** That flag is **owner-inbox only** (List `FlagListLPush` / `FlagListRPush` in `pkg/engine/list.go`; JSON `FlagJSONSet` / `FlagJSONDel` in `pkg/engine/json.go`; Bitmap `FlagBitmapSet` in `pkg/engine/bitmap.go`).

Rejected for v1: per-item replica apply; hintID change; op-log + snapshot-on-gap; Hash-class item-level with a “do not require both items” caveat; Bloom-style OR-merge of sketches (that would be correct *if* we merged, but handoff is LWW snapshot — see [Handoff is LWW, not merge](#handoff-is-lww-not-merge-locked)).

## Contract

### API (new; existing verbs unchanged)

On `pkg/engine.Engine`, `pkg/client.Client`, Cache proto, and **`cmd/sc`** (same PR as the type):

| Call | Meaning |
|------|---------|
| `HLLAdd(ks, name, item []byte)` | Redis `PFADD`. Creates the sketch if missing. **Does not return** Redis’s “changed” bool (ACK-only). |
| `HLLCount(ks, name) (n uint64, ok bool, err error)` | Redis `PFCOUNT` plus a SuperCache present-bit. Missing **name** → `ok=false`, `n=0`. Live sketch (including a theoretical estimate-0) → `ok=true`. |
| `Delete(ks, name)` | Existing Delete: whole-sketch tombstone. |

```go
HLLAdd(ctx context.Context, keyspace, name string, item []byte) error
HLLCount(ctx context.Context, keyspace, name string) (n uint64, ok bool, err error)
```

- `name` is the sketch identity; ring owner = `Owner(name)`. Validated with `validateKey` + `validateKeyLen` (per-keyspace `MaxKeyLen` applies to **name**).
- `item` is `[]byte`. **Empty item → `ErrInvalidArgument`** (`empty hll item`), same as List / Bloom / Set. Item length is bounded like Bloom / List (`pkg/engine/bloom.go`, `pkg/engine/list.go`): `len(item) > e.maxKeyLen` → `ErrKeyTooLarge`. Items are **hashed, not stored**.
- `HLLAdd` is ACK-only. SuperCache does **not** return whether any register changed (Redis `PFADD` does). A return payload would need a new Peer RPC. Do not add one.
- Each **owner** `HLLAdd` that applies assigns a **new stored version under the store mutex** (see [Version assignment](#version-assignment-locked)) and refreshes whole-sketch `ExpireAt` from keyspace `TTL` (`0` = none) — scheme B / Hash / List / Counter / JSON / Bitmap. ApplyPut paths use inbound `expireAt`, or `e.expireAt(TTL)` when the wire value is `0`. The inbound ApplyPut `Version: 1` on inbox flags is **not** the stored snapshot version.
- `HLLAdd` of an item that **does not change any register** still applies: new version, TTL slide, snapshot fan-out (a touch). Same as `BitSet` of an already-set bit / `JsonSet` of an equal node / `Incr(0)`.
- Get/Put on `ModeHLL` → `ErrInvalidArgument` (`use HLLCount` / `use HLLAdd`).
- HLL* on non-`ModeHLL` → `ErrInvalidArgument`.
- Cross-mode misuse (HLLAdd on ModeBitmap, BitSet on ModeHLL, …) → `ErrInvalidArgument`.

**Not in v1:** `PFMERGE`, return-was-changed, Redis dump compat, configurable `p`, sparse encoding.

### Present-bit vs Redis 0 (locked)

Redis `PFCOUNT` of a missing key returns `0`. SuperCache keeps a **present-bit** on name identity, matching Hash / List / Counter / JSON / Bitmap `BitGet`:

| State | `HasHLL` | `HLLCount` |
|-------|----------|------------|
| Missing name / expired / tombstone | false | `n=0`, **`ok=false`**, nil error |
| Live sketch, any estimate (including 0) | **true** | estimate, **`ok=true`** |
| Live sketch after first add | true | ≈1, `ok=true` |
| Live sketch after the same item twice | true | still ≈1 (idempotent add), `ok=true` |

A live HLL stays **present** until `Delete(name)`, even if the estimate is 0 (a zero register array is legal to *install*; owner `HLLAdd` never produces one — the first add sets at least one register). `HLLCount` of missing and of live-estimate-0 are both `n=0`; callers that need the distinction use `ok` or `HasLocal`.

`sc hllcount` prints the decimal count when `ok=true`, `(nil)` + exit 1 when `ok=false` (copy `cget` / `bitget`).

Do **not** return `ErrUnavailable` on `HLLCount`. Owner-down / `GetOrLoad` failure / `!Found` / `!IsHLL` → miss (`ok=false`, `n=0`, nil error). Same as `bFetchOwner` / `jFetchOwner`.

### Empty-until-delete (locked)

Prefer empty-until-delete (same spirit as Hash / List / Counter / JSON / Bitmap):

| Op | Result |
|----|--------|
| First `HLLAdd` of a missing name | **Creates** a dense 12 KiB sketch; `HasHLL` true; estimate ≈1 |
| `HLLAdd` of an already-seen item | Sketch stays live; estimate does not grow like `SetAdd` would; new version + TTL slide |
| There is no “HLL create empty” / “HLL clear” verb | First add creates; `Delete(name)` is the only drop |
| Live estimate 0 (if a zero blob is installed, or after rounding) | Stays until `Delete(name)` |
| `HLLAdd` never calls `Delete(name)` | Adding is not a tombstone |

### Size / DoS (locked)

The stored blob is a **fixed** 12 KiB (`hllx.DenseSize` = 12288). That is `<< keyspace.DefaultMaxValueSize` (1 MiB).

```text
dense = 16384 * 6 / 8 = 12288
max   = ks.MaxValueSize > 0 ? ks.MaxValueSize : e.maxValueSize
if max > 0 && dense > max                     → ErrValueTooLarge, no mutate
```

- **Initiating node** rejects `HLLAdd` when `max < DenseSize` **before** apply or `ApplyPut` forward (so clustered clients get `ErrValueTooLarge`, not a swallowed `!applied`).
- Owner `HLLAdd` also checks; `tooLarge=true`, **no mutate**.
- Inbox apply that still overflows (race on `MaxValueSize`, corrupt inbox) → `applied=false`. ACK-only `ApplyPut` cannot carry `ErrValueTooLarge`; the non-owner maps `!applied` to `ErrInvalidArgument` (`hll add rejected`). Owner-hit / single-node path **does** return `ErrValueTooLarge`.
- `UpdateKeySpace` / `Config.Validate`: `ModeHLL` with `MaxValueSize > 0 && MaxValueSize < 12288` **fails validation** (size is fixed; fail fast — unlike Bitmap, whose size depends on offset).
- `MaxBytes` may still **overshoot** one live `FlagHLL` (same as Set/Geo/List/Hash/JSON/Bitmap). One 12 KiB sketch is allowed to sit in an LRU that is slightly over budget. Do **not** fail `Validate` when `MaxBytes < 12288`.
- Incoming snapshot `len(blob) != DenseSize` → `HLLInstall` rejects (`applied=false`). No truncate, no pad.

Item DoS is the existing key-length cap (items are not stored).

### Keyspace

New mode `keyspace.ModeHLL` (next iota after `ModeBitmap`). `Mode.String()` **must** return `"HLL"` (else `/keyspaces` prints `Mode(11)`).

Current iota (`pkg/keyspace/config.go`): `LoadThrough=0` … `ModeBitmap=10`. `ModeHLL=11`.

| Field | Role |
|-------|------|
| `MaxBytes` | Cost budget. Live `FlagHLL` is LRU-protected; one sketch may **overshoot** |
| `TTL` | Expires the **whole** sketch; owner `HLLAdd` **slides** `ExpireAt` (scheme B) |
| `NegativeTTL` | Ignored |
| `TombstoneTTL` | On `Delete(name)` |
| `ReplicationFactor` | Same as KV / ModeBitmap |
| `MaxKeyLen` | Bounds `name` (and, via `e.maxKeyLen`, the item) |
| `MaxValueSize` | Must be `0` (engine default 1 MiB) or `≥ 12288`. Bounds the **register blob** |

No `HLLPrecision` / `HLLBits` knob. Do not reuse `BloomBits` — that is ModeBloom’s *m*.

### Replication (locked: snapshot like List / JSON / Bitmap)

| Hop | Payload |
|-----|---------|
| Client → any node → **owner** | `ApplyPut` `FlagHLLAdd` (item bytes) if this node is not owner |
| Owner → **replicas** | `FlagHLL` full snapshot after the op (dense 12 KiB + version + expire) |
| Handoff / `GetOrLoad` | `FlagHLL` install if incoming version **>** local (equal = ignore; tombstone blocks if incoming ≤ tombstone). **Not OR-merge** (that is Bloom). **Not per-register max-merge** (see below). |

`HLLAdd` is ACK-only — **no new Peer RPC**. Inbox flags + snapshot fan-out (List **push** / JSON `JsonSet` / Bitmap `BitSet` pattern). `HLLCount` never needs a Peer RPC: local extract or `GetOrLoad`.

**Version assignment (locked — one rule for store `HLLAdd`):**

Assign the stored snapshot version **inside the store mutex**. There is **no** second version space (`hllNextVersion` / `max(local, incoming)+1` is **not** used).

```text
if missing / expired (no live entry):     stored = 1          // create
if live FlagHLL or replacing tombstone:   stored = local.Version + 1
incoming `version` argument:              tombstone-gate floor only
                                          (reject if live tombstone && incoming <= tombstone.Version)
```

- Do **not** write the engine’s pre-lock `PeekVersion+1` as `Entry.Version`.
- Engine fans out **`PeekVersion` after the store write** (then `observeVersion` that same value). Never fan out the candidate passed in.
- Concurrent owner `HLLAdd`s serialize on the store mutex → distinct versions → `HLLInstall` (`incoming > local`, equal = ignore — same as `BInstall` / `JInstall` at `pkg/store/memory.go`) cannot drop the later snapshot.

**Owner-inbox vs replica-apply (locked — copy List / JSON / Bitmap, not Hash / Bloom):**

- Non-owner: `Transport.ApplyPut` `{Flags: FlagHLLAdd, Value: item bytes, Version: 1}`.
- Owner `ApplyPut` of that flag: **apply the op** (store `HLLAdd` first). Pass `PeekVersion+1` (0→1 if missing) **only** as the tombstone-gate floor. Do **not** use inbound `Version: 1` as the stored version. If the store reports a mutate, `ver, _ := PeekVersion(name)` then `ks.observeVersion(name, ver)` + `hllReplicateSnapshot(..., ver, ...)`.
- Replica `ApplyPut` of `FlagHLLAdd`: **ignore** (`return false, nil`) if this node is not owner — same guard as `IsListLPush` / `IsJSONSet` / `IsBitmapSet` in `pkg/engine/engine.go` `ApplyPutWithRingGen`. Do not send inbox flags to replicas.
- `FlagHLL` → `HLLInstall` version gate only.

**Owner-local `HLLAdd`:** same as inbox apply — store first, fan out `PeekVersion` after write.

**Non-owner `applied=false`:** initiating node already rejected empty / oversize **item** and `DenseSize > max`. Owner reject (tombstone, non-HLL entry) surfaces as `ErrInvalidArgument` (`hll add rejected`). Encoded `ErrValueTooLarge` is guaranteed on the **owner-hit / single-node** path.

**Reads (locked: same as `bFetchOwner` / `jFetchOwner` / `hFetchOwner`):**

- If `HasHLL` local → extract estimate from the **local** registers. Replica snapshot may **lag**. **Do not** owner-forward a local hit.
- Else if this node is owner → missing sketch → `ok=false`, `n=0`.
- Else → `hllFetchOwner` (copy of `bFetchOwner`):
  - `GetOrLoad` RPC error / owner down / `!Found` / `!IsHLL` → **miss** (`ok=false`, `n=0`, nil error). Do **not** return `ErrUnavailable` on reads.
  - `holdsReplica` → `HLLInstall` then extract.
  - Non-replica → use `ent.Value` in process; **do not** `HLLInstall`.

Owner down on `HLLAdd` → `ErrUnavailable` (no ACK authority), same as Put / BitSet / JsonSet. Do not apply locally.

```mermaid
sequenceDiagram
  participant C as Client
  participant N as Non-owner
  participant O as Owner
  participant R as Replica
  C->>N: HLLAdd(name, item)
  N->>O: ApplyPut FlagHLLAdd inbox Version=1
  O->>O: HLLAdd (stored=local+1 under mutex) + PeekVersion + replicate FlagHLL
  O->>R: ApplyPut FlagHLL snapshot
  O-->>N: applied
  N-->>C: OK
  Note over R: HLLInstall only; ignore inbox flags
  C->>R: HLLCount(name)
  Note over R: HasHLL → local estimate (may lag)
  C->>N: HLLCount(name)
  alt N holds replica copy
    N-->>C: local estimate
  else non-replica
    N->>O: GetOrLoad(name)
    O-->>N: FlagHLL snapshot
    N-->>C: extract Count
  end
```

**Hint-after-down (normative):** two `HLLAdd`s of **different** items while replica B’s Peer is down; then start B and wait for hint flush. The pending hint is the **latest snapshot** → B’s sketch contains **both** items. Copy List/JSON/Bitmap ring/transport/down setup (`TestListHintAfterPeerDownKeepsBothPushes` / `TestJSONHintAfterPeerDownKeepsBothPaths` / `TestBitmapHintAfterPeerDownKeepsBothBits`). **Do** require both items (this is why we chose snapshot). **Do not** copy Hash’s “do not require both fields.”

Because registers are not a public API, the test asserts:

1. After flush, `engB.HLLCount` **equals** `engA.HLLCount` (identical snapshot ⇒ identical estimate).
2. Owner count is in the same ballpark as **2** (e.g. `1…4`) so a lost first item (`Count≈1`) fails.
3. Optional stronger check: `Peek` `Value` bytes equal on A and B (`DenseSize`).

A third `HLLAdd` “to poke the pool” (Bitmap’s `BitSet(16)`) is allowed only if the assert still requires **both original items**, not only the poke.

### Handoff is LWW, not merge (locked)

`hllx.Merge` (per-register `max`) is implemented and unit-tested because that is the mathematically correct union of two sketches. **Handoff / replica apply / `GetOrLoad` install must not call it.**

Two concurrent writers on the **same name** serialize on the owner store mutex, so snapshots are **total-ordered**. Incoming `FlagHLL` with `version > local` **replaces** the blob (`HLLInstall`). Equal = ignore. Tombstone `<=` blocks. This is `BInstall` / `JInstall`, **not** Bloom `BloomMerge` (bitwise OR).

Do **not** max-merge incoming snapshots. A stale merged-in sketch would resurrect registers the owner had already… HLL cannot delete registers, so a merge is “safe” for cardinality but **wrong** for SuperCache LWW: a delayed lower-version snapshot must not raise registers that a later Delete+recreate (or a later owner generation) replaced. Version gate + replace is the contract.

### What existing clients can assume

- CacheOnly / LoadThrough / Bloom / Set / ZSet / Geo / List / Hash / Counter / JSON / Bitmap unchanged if they never open `ModeHLL`.
- No new default node keyspace (`-demo-keyspace` stays `demo` / `tags` / `board` / `profile` / `doc` / `flags`).
- Rolling: do **not** register a `ModeHLL` keyspace until every node has the HLL `ApplyPut` branches. An old node would fall through `ApplyPutWithRingGen` to `AcceptIfNewer` and treat `Mode=11` as KV.

## Approach

### Algorithm (locked — stdlib-only, not Redis-numeric-compat)

Package **`pkg/hllx`** (`hll` / `hyperloglog` are fine but `hllx` matches `pkg/jsonx` / `pkg/listx` / `pkg/hashx` / `pkg/bitmapx`).

**Parameters (locked — Redis-class size, SuperCache hash):**

| Knob | Value |
|------|--------|
| Precision `p` | 14 |
| Registers `m` | `1<<14` = 16384 |
| Register width | 6 bits (values 0…63) |
| Encoding | dense only, 12288 bytes, **no header** |
| Hash | alloc-free **FNV-1a 64** (same constants as `hash/fnv`) |

`cespare/xxhash/v2` is only an **indirect** dep (`go.mod` via `github.com/redis/go-redis/v9`). Do **not** take it as a direct module. Bloom already uses `hash/fnv` (`pkg/bloom/bloom.go` `hash2`); the ring uses `fnv.New64a()` (`internal/ring/ring.go`). HLL inlines FNV-1a so `HLLAdd` does not allocate a `hash.Hash64`.

Estimates **will not match** Redis `PFCOUNT` on the same items. Redis uses MurmurHash64A (`0xadc83b19`), a 16-byte `HYLL` header, sparse↔dense promotion, and empirical bias tables (`src/hyperloglog.c`). SuperCache has no Redis dump import. Tests lock **error bounds**, not Redis parity.

**Index / ρ (locked — Flajolet high bits, not Redis low bits):**

```text
x     = FNV-1a-64(item)
idx   = x >> (64-p)                         // top p bits → register index
w     = x << p                              // remaining 50 bits, left-justified
rho   = LeadingZeros64(w) + 1               // w==0 → (64-p)+1 = 51
rho   = min(rho, 63)                        // 6-bit saturate
M[idx] = max(M[idx], rho)
```

Cite: Flajolet, Fusy, Gandouet, Meunier, *[HyperLogLog: the analysis of a near-optimal cardinality estimation algorithm](https://algo.inria.fr/flajolet/Publications/FlFuGaMe07.pdf)* (AOFA 2007). Wikipedia [HyperLogLog](https://en.wikipedia.org/wiki/HyperLogLog) for the estimator. Redis `src/hyperloglog.c` for **6-bit packing layout only** (not hash, not bias tables).

**Estimator (locked):**

```text
α_m = 0.7213 / (1 + 1.079/m)          // m = 16384 ≥ 128
E   = α_m * m² / Σ_j 2^{-M[j]}

// small-range (linear counting)
if E ≤ 2.5*m:
    V = |{ j : M[j] == 0 }|
    if V > 0:
        E = m * ln(m / V)

// large-range: NONE in v1
// The classical 2^32 correction is for 32-bit HLL and would fire around
// ~1.4e8, corrupting a 64-bit sketch. 2^64 is unreachable in practice.

return uint64(math.Floor(E + 0.5))    // nearest integer
```

Consequences tests must lock:

| Input | Estimate |
|-------|----------|
| All-zero registers (empty blob / never added) | **0** (linear counting, `V=m`) |
| One distinct item | ≈ **1** (allow `1…2`) |
| Same item twice | **unchanged** vs one add (idempotent; not Set-like) |
| N = 10_000 distinct (deterministic 8-byte LE i=0…N-1) | `\|est-N\|/N < 0.03` (typical ~0.8%; 3% is the CI bar) |
| Many distinct grow | `Count(N=1000) > Count(N=10)` |

**Dense packing (locked — 6-bit, Redis bit layout, no header):**

Register `i` occupies bits `[i*6, i*6+6)` in the 12288-byte string, little-endian within the byte stream — the Redis `HLL_DENSE_GET_REGISTER` / `HLL_DENSE_SET_REGISTER` layout **without** the 16-byte Redis header. This is compactness only (12 KiB, not 16 KiB of 1-byte regs). It does **not** make `PFCOUNT` match.

```go
// bit 0 of register i is the low bit of that 6-bit field.
byte = (i * 6) / 8
fb   = (i * 6) % 8
// value spans one or two bytes; mask with 0x3f
```

**Merge (internal only):**

```go
func Merge(dst, src []byte) error // per-register max; both must be DenseSize
```

Used in `pkg/hllx` tests. **Never** called from `HLLInstall` / handoff / replica apply.

```go
package hllx

const (
    Precision = 14
    Registers = 1 << Precision // 16384
    RegBits   = 6
    DenseSize = Registers * RegBits / 8 // 12288
)

var (
    ErrSize  = errors.New("hllx: bad register blob size")
    ErrEmpty = errors.New("hllx: empty item")
)

// New returns a zeroed dense sketch (DenseSize bytes).
func New() []byte

// Add hashes item into regs in place. No-op (and no panic) if len(regs)!=DenseSize
// or len(item)==0 — the engine rejects those first.
func Add(regs []byte, item []byte)

// Count is the corrected HLL estimate. All-zero → 0. Bad size → 0.
func Count(regs []byte) uint64

// Merge writes per-register max(dst, src) into dst.
func Merge(dst, src []byte) error

func GetReg(regs []byte, i int) uint8
func SetReg(regs []byte, i int, v uint8)
func Hash64(item []byte) uint64 // alloc-free FNV-1a 64
```

Inline FNV-1a (stdlib constants; do not call `fnv.New64a()` on the add path):

```go
const (
    offset64 = 14695981039346656037
    prime64  = 1099511628211
)

func Hash64(item []byte) uint64 {
    h := uint64(offset64)
    for _, c := range item {
        h ^= uint64(c)
        h *= prime64
    }
    return h
}
```

### Store (`pkg/store`)

Last shipped bits in `pkg/store/entry.go`: `FlagBitmap` `1<<23`, `FlagBitmapSet` `1<<24`. Next free is `1<<25`:

```go
FlagHLL    uint32 = 1 << 25 // value is dense 12 KiB register snapshot
FlagHLLAdd uint32 = 1 << 26 // owner-inbox: raw item bytes
```

`Entry.IsHLL()` / `IsHLLAdd()`.

**No `hllCache` / `hllDirty`.** The live structure **is** `Entry.Value` (like Bitmap / Counter / Bloom, unlike JSON/List/Hash). Mutate registers **in place** under the store mutex. **Do not** add `flushHLLValueLocked` — a Get/Peek helper that is easy to get wrong on the KV hot path. Peek/Get already clone `Value`.

```go
// store.Store
HLLAdd(key string, item []byte, version uint64, expireAt int64, maxValue int) (applied, tooLarge bool)
HLLCount(key string) (n uint64, ok bool)
HasHLL(key string) bool // live unexpired FlagHLL
HLLInstall(key string, blob []byte, version uint64, expireAt int64) bool // incoming > local
```

**`HLLAdd` (locked).** Gate first; **only a successful apply mutates**.

1. Live non-HLL → `applied=false`; no write.
2. Live unexpired tombstone and `version <=` tombstone → `applied=false`; no write.
3. `maxValue > 0 && DenseSize > maxValue` → `tooLarge=true`, `applied=false` (**before** allocate).
4. Missing / expired / tombstone with `version >` tombstone → **create**: `hllx.New()` + `hllx.Add`, `Version=1` (or `tombstone.Version+1` when replacing a tombstone), `Flags=FlagHLL`.
5. Live HLL: `hllx.Add` **in place** on `it.entry.Value` (same backing array; `len==DenseSize`).
6. Commit under this mutex: `Version = 1` on create (missing/expired) or `local.Version+1` when replacing live HLL / a superseded tombstone; `Flags=FlagHLL`; slide `ExpireAt` if `expireAt != 0`; cost; `MoveToFront`; `evictLocked`. Incoming `version` is **not** written (tombstone-gate floor only — step 2).
7. An add that does not raise any register **still** commits (version + TTL). There is no “unchanged → skip” path.

In-place add may mutate `it.entry.Value` bytes under the mutex. Peek/handoff clone.

**`HasHLL` (locked):** copy `HasBitmap` / `HasJSON`’s **flag** gate — live, unexpired, not tombstone, `IsHLL`. Do **not** require `len(Value) > 0` and do **not** require `Count > 0`.

**`HLLCount`:** `HasHLL` + `hllx.Count`. Missing → `ok=false`, `n=0`.

**`HLLInstall`:** same gate as `BInstall` / `JInstall` / `CInstall` (`incoming > local`; equal ignore; tombstone `<=` blocks). Reject `len(blob) != DenseSize`. Replace with a **copy** of `blob`. No decode beyond the size check.

**Stored version (locked):**

```text
stored = local.Version+1          // live FlagHLL, or replace tombstone after gate
stored = 1                        // HLLAdd create (missing / expired; no local entry)
incoming version                  // tombstone-gate floor only
```

Engine **must** replicate `PeekVersion` **after** `HLLAdd` returns applied, not the candidate it passed in. `observeVersion` that same post-write version.

Protect live `FlagHLL` in `lruVictim` (`pkg/store/memory.go` today lists Bloom/Set/ZSet/Geo/List/Hash/Counter/JSON/Bitmap).

`Set` / `AcceptIfNewer` need no HLL cache to clear.

```go
func (e *Engine) applyHLLAdd(ks *ksRuntime, name string, item []byte, expireAt int64) bool {
    if len(item) == 0 {
        return false
    }
    if expireAt == 0 {
        expireAt = e.expireAt(ks.cfg.TTL)
    }
    max := e.maxValueSize
    if ks.cfg.MaxValueSize > 0 {
        max = ks.cfg.MaxValueSize
    }
    cur, _ := ks.store.PeekVersion(name)
    gate := cur + 1 // tombstone floor only; store assigns the stored version
    ok, tooLarge := ks.store.HLLAdd(name, item, gate, expireAt, max)
    if !ok || tooLarge {
        return false
    }
    ver, _ := ks.store.PeekVersion(name)
    ks.observeVersion(name, ver)
    e.hllReplicateSnapshot(ks, name, ver, expireAt)
    return true
}
```

## Security & privacy

No new auth surface. Document names/items ride the existing Cache gRPC (TLS) and Peer ApplyPut (mTLS). Do not log item bodies or register blobs (items can be user IDs / emails). Limits (`MaxKeyLen` on name and item; `MaxValueSize` ≥ 12288; `MaxBytes` may overshoot one live HLL) are the DoS bound — the blob is fixed-size, so the bomb is “many names”, not “one huge add”. Same tenant isolation: keyspace config is local and must match across nodes.

Owner **store mutex** serializes `HLLAdd` **and** assigns `stored = local.Version+1` (or `1` on create). There is **no** extra engine owner-mutate mutex — same as Hash/List/JSON/Bitmap. Two clients mutating the same name apply in store-lock order; successive snapshots have distinct versions so `HLLInstall` cannot drop the later one. A client that retries `HLLAdd` after a timeout may double-apply (idempotent for the *item*, still a version touch). SuperCache does not have request ids.

HLL is **approximate**. Do not use `HLLCount` as an exact billing meter or unique-user ledger.

## Observability

Reuse existing fan-out / hint / `staleSkip` / store hit-miss counters. No new required metrics in v1. Optional later: HLL count histogram. Wrong-mode, empty item, and oversize map through `grpcmap`.

## Rollout / rollback

- Opt-in: nothing happens until an operator registers a `ModeHLL` keyspace on **every** node.
- Deploy the HLL build cluster-wide first; then `UpdateKeySpace`.
- Rollback: stop writing HLLAdd; `Delete(name)` or drop the keyspace. No on-disk format.
- No feature flag (mode is the flag).
- Example is in-process only; it does not change node defaults.

## Open points (resolved in this draft)

1. **Naming:** **ModeHLL** / **HLLAdd** / **HLLCount**. Not ModeHyperLogLog / PfAdd. `String()=="HLL"`.
2. **Fan-out:** **snapshot `FlagHLL` only**; inbox flags never go to replicas.
3. **Return path:** none; ApplyPut inbox + snapshot (List push). `HLLAdd` does **not** return Redis’s changed bool.
4. **Present-bit:** missing **name** → `HLLCount` `ok=false`; live estimate 0 → `ok=true`.
5. **Empty-until-delete:** first add creates; live estimate 0 stays; `Delete(name)` only.
6. **Size:** fixed 12 KiB; `MaxValueSize < 12288` fails Validate and HLLAdd (`ErrValueTooLarge`). `MaxBytes` may overshoot.
7. **Version:** **one rule** — `stored = local.Version+1` (or `1` on create) under the store mutex; incoming `version` is tombstone-gate only; engine fans out `PeekVersion` after the write.
8. **Algorithm:** FNV-1a 64, `p=14`, 6-bit dense, Flajolet estimator, no large-range correction, **not** Redis-numeric-compat.
9. **Merge:** implemented internally; handoff is **LWW replace**, not max-merge, not Bloom OR.
10. **hintID:** unchanged. Item-level replica FlagHLLAdd is **rejected**.
11. **Example:** **same PR**, `examples/hll`, name `visitors`, keyspace `uniq`.
12. **Demo KS:** **not** in this PR (`flags` is Bitmap).
13. **CLUSTER_FLOWS:** table + E11 `HLLCount` + OPS; HLLAdd not on E10.
14. **Hint test:** both items present after snapshot replay (`Count` equal + owner ≈ 2).
15. **Flags:** `1<<25` / `1<<26`.
16. **Store cache:** none; Value is the registers; no Get/Peek flush.
17. **PLAN §1:** ModeHLL allowed; do not invent a fight; `PFMERGE` stays out as multi-key.
18. **Empty item:** **reject** (`ErrInvalidArgument`).
19. **Precision knob:** none in v1.
20. **OpenAPI:** 0.9.0 → 0.10.0.

## Rejected alternatives

| Idea | Why not |
|------|---------|
| `ModeSet` + `SetCard` | Exact, O(n) memory; not a sketch |
| `ModeCounter` | Not distinct |
| `ModeBloom` | Membership, not cardinality; OR-merge |
| `ModeBitmap` `BitCount` | Counts set bits in a packed vector, not hashed items |
| `ModeZSet` `ZCard` | Exact members |
| KV / Hash / JSON / List / Geo | Wrong shape; Put LWW-clobbers |
| Item-level `FlagHLLAdd` to replicas | Lost hints drop the other item; `hintID` is `(ks, name)` |
| Bloom-style hintID `(ks, name, item)` for HLL | Touches global hint path; Bloom is the documented exception |
| Hash-class item-level + “don’t require both items” | Accepts silent data loss; we can snapshot a fixed 12 KiB instead |
| Change hintID in this PR | Touches global hint path; separate design |
| Client-built snapshot ApplyPut to owner | Two writers clobber; owner must apply the **op** |
| New Peer RPC / return changed-bool | HLLAdd is ACK-only; ApplyPut suffices |
| `PFMERGE` in v1 | Multi-key; PLAN already excludes multi-key atomicity |
| OR-merge or max-merge incoming snapshots | Bloom’s rule. HLL handoff is LWW; delayed lower version must not resurrect a replaced name |
| Redis-compatible Murmur + sparse + bias tables | Extra surface; no dump import; tests lock error bounds instead |
| Direct `xxhash` dep | Indirect only today; stdlib FNV is enough |
| Configurable `p` as a keyspace field | Complicates Validate / install size; lock Redis-class 14 |
| Sparse encoding | First add would be a different layout; dense is one blob |
| 1-byte registers (16 KiB) | Prompt locks 6-bit / 12 KiB |
| Large-range 2^32 correction | Wrong for 64-bit hashes |
| Default HLL demo keyspace | `flags` just shipped Bitmap |
| `HLLAdd` pre-lock nextVersion as stored | Two version spaces; replica `HLLInstall` can drop the later snapshot |
| Peek/Get `flushHLL*` helper | Unnecessary (Value is encoded) and a Get-hit alloc risk |
| Invent a PLAN §1 fight | That line is “not RESP / not a Redis clone”; ModeHLL is a SuperCache mode |
| Names `ModeHyperLogLog` / `PfAdd` | Breaks Geo/Hash short-name convention; `String()` would be noisy |
