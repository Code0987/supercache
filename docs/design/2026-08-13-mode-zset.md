# Sorted set type (`ModeZSet`)

**Status:** approved  
**Branch:** `feat/mode-zset`

## Problem

SuperCache already has:

| Mode | Strength |
|------|----------|
| CacheOnly / LoadThrough | opaque `key → []byte` |
| ModeBloom | approximate membership |
| ModeSet | exact membership, no order |

There is no **ordered membership with scores** (leaderboards, time-ordered feeds, ranked tags). Callers today either store one KV per member (`rank:board:user` → score) and cannot range efficiently, or keep a sorted set outside SuperCache.

## Non-goals

- Lexicographic-only sets without scores (use ModeSet)
- Multi-key ZUNION/ZINTER store-side (client-side later)
- Per-member TTL inside a zset (whole-name `TTL` only)
- Geospatial, streams, lists, hashes
- Changing RF / tombstone / existing Get/Put/Delete / Set / Bloom contracts
- Persistence across process restart
- Unbounded zsets: `MaxBytes` still bounds the encoded entry

## Contract

### API (new; existing verbs unchanged)

On `pkg/engine.Engine`, `pkg/client.Client`, Cache proto, and **`cmd/sc`** (same PR as the type):

| Call | Meaning |
|------|---------|
| `ZAdd(ks, name, member, score float64)` | Insert or **update score** of `member` in named zset. Creates zset if missing. |
| `ZRem(ks, name, member)` | Remove `member` if present. No-op if missing / zset missing. |
| `ZScore(ks, name, member) (score float64, ok bool, err error)` | Score if present. Missing member or zset → `ok=false`, nil error. |
| `ZCard(ks, name) (int, error)` | Member count. Missing → `0`, nil error. |
| `ZRange(ks, name, start, stop int) ([]ZMember, error)` | By **rank** (0-based, inclusive), ascending score then member bytes. Negative indices like Redis (`-1` = last). Missing → empty. |
| `ZRangeByScore(ks, name, min, max float64) ([]ZMember, error)` | Inclusive score window, ascending. Missing → empty. |
| `Delete(ks, name)` | Existing Delete: whole zset tombstone. |

```go
type ZMember struct {
	Member []byte
	Score  float64
}
```

- `name` is the zset identity; ring owner = `Owner(name)`.
- `member` is `[]byte`, same max length as a key (`MaxKeyLen`).
- **Score** is IEEE-754 `float64` (NaN rejected as `ErrInvalidArgument`). `+Inf` / `-Inf` allowed if useful for sentinels; document.
- **Equal scores:** stable order by raw **member** byte order (Redis-like).
- Get/Put on `ModeZSet` → `ErrInvalidArgument`.
- Z* on non-`ModeZSet` → `ErrInvalidArgument`.
- Cross-mode misuse (ZAdd on ModeSet, SetAdd on ModeZSet, etc.) → `ErrInvalidArgument`.

**Not in v1 (optional later):** `ZRank`, `ZRevRange`, `ZCount`, `ZIncrBy`, `ZPopMin`/`ZPopMax`, WITHSCORES-only variants (Range always returns scores).

### Keyspace

New mode `keyspace.ModeZSet`.

| Field | Role |
|-------|------|
| `MaxBytes` | Bounds encoded zset blob + envelope |
| `TTL` | Expires the **whole** zset |
| `NegativeTTL` | Ignored |
| `TombstoneTTL` | On `Delete(name)` |
| `ReplicationFactor` | Same as KV / ModeSet |

No extra sizing knobs in v1.

### Replication

Same pattern as **ModeSet** (owner-serialized writes + item-level fan-out + versioned snapshot handoff):

| Op | Owner | Replicas |
|----|--------|----------|
| `ZAdd` | upsert member/score under store mutex; bump set version | `FlagZSetAdd` apply (member + score in value) |
| `ZRem` | remove member; bump version | `FlagZSetRem` apply |
| `Delete(name)` | tombstone | `ApplyDelete` |
| Handoff | full snapshot | `FlagZSet` install if incoming version ≥ local |

**Wire (locked, match ModeSet/Bloom):** reuse **ApplyPut** with new flags (no required new peer RPC names):

| Flag | Value payload |
|------|----------------|
| `FlagZSet` | full encoded zset (handoff) |
| `FlagZSetAdd` | encoded single `{score, member}` |
| `FlagZSetRem` | member bytes only |

Hints: `(ks, name, "zadd", member)` / `(ks, name, "zrem", member)`; tombstone on `name` supersedes pending member ops.

Non-replicas: `ZScore` / `ZCard` / `ZRange*` **forward to owner** (GetOrLoad of the zset blob or dedicated path). Replicas in RF keep a local copy for local reads.

### Concurrent ZAdd of same member with different scores

Owner serializes; **last write wins** for that member’s score. Replicas apply ops with post-op version gates (same as ModeSet).

### What existing clients can assume

- CacheOnly / LoadThrough / ModeBloom / ModeSet unchanged if they never open `ModeZSet`.
- No new default keyspace on the node unless demos opt in (examples PR separate or same as demos).

## Approach

### In-memory model (`pkg/zset`)

```go
type ZSet struct {
	// member string(item) → score
	scores map[string]float64
	// order: sorted by (score asc, member asc); rebuilt or maintained on mutate
	// v1: rebuild sorted index on each mutate is OK with lazy encode + cache
}
```

Ops: `Add(member, score)`, `Rem(member)`, `Score(member) (float64, bool)`, `Card()`, `Range(start, stop int)`, `RangeByScore(min, max float64)`.

**Encode (canonical):** sequence of records sorted by (score, member):

```text
for each (score, member) in order:
  8 bytes IEEE float64 little-endian score
  uvarint(len(member)) + member bytes
```

Decode rebuilds `scores` map + can rebuild order.

### Store

New flags: `FlagZSet`, `FlagZSetAdd`, `FlagZSetRem`.

Under mutex (mirror ModeSet):

- Live `zCache *zset.ZSet` + `zDirty` for lazy encode.
- `ZAdd` / `ZRem` mutate cache; approximate cost via `ApproxWireBytes()`; encode on Peek/Get.
- `ZScore` / `ZCard` / `ZRange*` use cache (0 alloc hot path for score/card when warm).
- `ZInstall(key, blob, version, expireAt)` versioned snapshot replace.
- Protect live zset entries from LRU like Set/Bloom.

`Store` interface gains the corresponding methods.

### Engine

`pkg/engine/zset.go` (or `sortedset.go`):

- Mode checks, key/member limits, reject NaN score.
- Owner local + `replicate` FlagZSetAdd/Rem.
- Non-owner: ApplyPut to owner (same as SetAdd).
- ApplyPut branches for FlagZSet*.
- Get/Put reject ModeZSet.
- GetOrLoadLocal returns FlagZSet entry for owner fetch (like ModeSet).

### Client / proto / sc

Cache RPCs:

```protobuf
rpc ZAdd(ZAddRequest) returns (ZAddResponse);       // score double, member bytes
rpc ZRem(ZRemRequest) returns (ZRemResponse);
rpc ZScore(ZScoreRequest) returns (ZScoreResponse); // present bool + score
rpc ZCard(ZCardRequest) returns (ZCardResponse);
rpc ZRange(ZRangeRequest) returns (ZRangeResponse); // start/stop int32
rpc ZRangeByScore(ZRangeByScoreRequest) returns (ZRangeResponse);
// ZMember { bytes member; double score; }
```

`pkg/client` wrappers.

**`cmd/sc` (required in the product PR):** same style as `bloom add|test`:

| CLI | Maps to |
|-----|---------|
| `zadd <name> <score> <member>` | `ZAdd` |
| `zrem <name> <member>` | `ZRem` |
| `zscore <name> <member>` | `ZScore` (print score or `(nil)`) |
| `zcard <name>` | `ZCard` |
| `zrange <name> <start> <stop>` | `ZRange` (print `score member` lines) |
| `zrangebyscore <name> <min> <max>` | `ZRangeByScore` |

Uses session keyspace (`-k` / REPL), same as get/put/bloom. Help text updated.

Note: ModeSet shipped without `sc set …` yet; ZSet will not skip CLI. (Optional follow-up: add `sc set add|rem|contains|card|members` for ModeSet.)

## Open points (resolve in review)

1. **Naming:** `ModeZSet` + `ZAdd`… (Redis-ish) vs `ModeSortedSet` + `SortedSetAdd`… — design defaults to **Z\*** for brevity.  
2. **ZRangeByScore in v1** — included; drop if you want a smaller first cut.  
3. **±Inf scores** — allow vs reject.  
4. **Empty zset after last ZRem** — keep empty entry (Card 0) until `Delete(name)` (same as ModeSet).  

## Rejected alternatives

| Idea | Why not |
|------|---------|
| One KV key per member | No efficient range; RF multiplies keys |
| Overload ModeSet with optional scores | Breaks ModeSet contract; mixed clients |
| Full snapshot LWW every ZAdd | Correct under owner but O(n) network always; item-level matches ModeSet |
| Skiplist package dependency | Unnecessary for in-process v1 sizes; sorted slice + map is enough with MaxBytes |
